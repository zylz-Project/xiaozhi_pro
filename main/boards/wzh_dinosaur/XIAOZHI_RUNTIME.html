限制设备只能在合法状态间切换

⚙️ Application

FreeRTOS 事件组织者，主循环调度中心

🦖 wzh_dinosaur

电源、五路舵机、W25Q256 离线声音、情绪动作

5 主事件循环

Application::Run() 把主任务优先级设为 10，永久等待 Event Group：

事件驱动模型
flowchart LR A["🌐 网络回调"] --> E["⚡ Event Group"] B["🎤 音频任务"] --> E C["⏰ 定时器"] --> E D["🔘 按键"] --> E E --> F["🔔 唤醒主循环"] F --> G["📋 主任务串行处理"]

9 两种服务端传输方式

单连接模式 — 一条连接同时传输：

  • 文本 JSON 控制消息
  • 二进制 Opus 音频包

打开通道时发送 hello 声明协议版本、MCP 能力、音频格式。

双通道模式：

  • MQTT：会话控制、JSON 消息、MCP、STT/TTS 状态
  • UDP：实时 Opus 音频，AES-CTR 加解密

UDP 通过时间戳和序列号检查重复、乱序或丢包。

上层不关心底层实现，统一接口：

  • OpenAudioChannel() / CloseAudioChannel()
  • SendAudio()
  • SendStartListening() / SendStopListening()
  • SendAbortSpeaking()
  • SendMcpMessage()

队列规则：

  • 容量为 1 的 action_queue_，只保留最新待执行意图
  • 1.2 秒内重复动作合并
  • 队列满时替换旧请求，保留最新意图
  • 完整动作 20 ms 插值，待机目标 50 ms 更新；移动帧至少 420 ms、最快轴平均不超过约 80 度/秒
  • 同一关键帧内五轴共用进度，同步开始、同步到达
  • 单独移动使用原有三次 SmoothStep；连续同向关键帧用单调 Hermite 轨迹穿过中间姿态，不再每帧刹停且不过冲
  • 随机左右镜像，减少机械重复
  • 声音/生命偏移不写回基础姿态，镜像不重复翻转 KEEP 轴，动作结束准确回中
  • 12 秒慢呼吸后回默认中位停顿约 4 秒，偏姿后回中停留 9～15 秒 🫁
  • 八种待机小表情随机变化，相邻两次不重复，完成后自然回中
  • Flash 自主表演先选声音再按名称/时长选择动作；24 套完整 + 24 套短声 + 7 套怒吼变体，共 55 套声音表演，相邻轨迹不复读
  • 所有“叫声音效合集 (N)”/怒吼/长啸/咆哮/roar 按时长进入怒吼库：先明显仰头，再做有限且平衡的横向细节；不随机镜像，声音主要加强仰头和抬尾
  • 在线 TTS、本地声音和系统提示音按实际 PCM 包络驱动五轴同步随动
  • roar-onset-v3：怒吼首帧直接正面仰头，默认起点约 900 ms；长声只拉伸后续表演，回中独立计时。侧仰时头部反向补偿，尾巴配重
  • stories-v4：新增亲近回望、侧耳复核、短吼轻收声和长吼高位弧线。随机缩放/镜像后先夹紧物理目标再插值，减少极限位空等；生命微动两端平滑淡入淡出，短于 900 ms 的帧按时长减弱微动。触发间隔不变
  • 2026-09-13 用户确认五轴方向。新增高低巡视 discover-canopy、探身招呼 happy-invite、贴地取食 eat-graze；取食正面到 IO17=180，深低头时声音抬头叠加减弱至零。显式 0/180 落点不受随机缩幅影响，保留同步慢速和原触发间隔
  • Roar pose 日志记录最终软件输出角度；显式调用 self.dinosaur.test_servo（gpio=17/16/15/8/18）可关闭叠加并逐路小范围核对实际装配，结束回默认姿态

16 在线和离线模式切换

🟢 在线模式

  • 正在连接会话、聆听、说话或录音测试 → online=true
  • 先做 listen 动作
  • 停止离线随机动作
  • 不播放 W25Q256 声音
  • 接收 llm.emotion + MCP
  • 在线 TTS 按真实响度驱动颈、头、尾动作

🟡 离线模式

  • idle 或没有语音会话 → online=false
  • 做 discover + 本地声音
  • 继续空闲呼吸动作
  • 前一动作结束 5～13 秒后再选下一段声音
  • 先选 W25Q256 声音，再按名称/时长选择动作
离线模式不是另一套 app_main——XiaoZhi 主循环、AudioService 和板级任务仍然运行，只是没有服务端语音会话。

17 W25Q256 离线声音链路

离线声音播放流程
flowchart LR Select["📂 选择实际 Flash 声音"] --> Classify["🧭 名称/时长选动作"] Select --> Queue["📋 dino_audio 队列"] Queue --> SPI["💾 分块读 W25Q256"] SPI --> OGG["📦 OggDemuxer"] OGG --> Decode["🔊 解码队列"] Decode --> Output["🔉 ES8311 扬声器"] SPI --> Started["▶️ 确认目标声音开始"] Started --> Motion["🦖 专属/完整编舞"] Classify --> Motion Output --> Envelope["〰️ 真实 PCM 包络"] Envelope --> Motion

DinosaurAudio 复用 AudioService，不与在线 TTS 产生驱动冲突。动作线程最多等待 300 ms 确认目标文件开始；当前共有 24 套完整动作、24 套短声动作和 7 套怒吼动作。旧工程动作仅尾上下按 180-angle 换算，其余轴不反向；移植动作改为五轴同步起停。长声音使用完整编舞并只向慢方向拉伸，真实 PCM 强弱还会同步控制全身舒展与收束。

18 电源与电池任务

dino_power 任务职责：

  • GPIO7 维持电源锁存
  • 每 20ms 读取模拟电源键
  • 每 20ms 读取 IO5 触摸网络，3 次中值滤波并做 100ms 稳定判定
  • 长按 1.5s → 拉低 GPIO7 关机
  • 每 5s 采样电池 ADC ×32 取平均
  • 3.2～4.2V → 0～100% 线性映射
无充电检测脚 → charging=false, discharging=true 固定报告。电量只是粗略估算。
