1 一句话理解整个系统

XiaoZhi 固件的核心是一个由事件驱动的 Application 主循环，由 6 大模块协同工作：

🎯 Board

音频、网络、显示、电池等硬件能力

🎤 AudioService

麦克风采集、唤醒词、Opus 编解码、播放

🌐 Protocol

音频 & JSON 消息 → 服务端 ASR/TTS/LLM

🔒 StateMachine

限制设备只能在合法状态间切换

⚙️ Application

FreeRTOS 事件组织者，主循环调度中心

🦖 wzh_dinosaur

电源、五路舵机、W25Q256 离线声音、情绪动作

系统架构图
flowchart TD Main["🚀 app_main"] --> App["⚙️ Application"] App --> Board["🎯 Board / WzhDinosaur"] App --> State["🔒 DeviceStateMachine"] App --> Audio["🎤 AudioService"] App --> Protocol["🌐 Protocol"] App --> MCP["🔧 McpServer"] Board --> Wifi["📶 WifiBoard / WiFiManager"] Board --> Codec["🎵 ES8311 AudioCodec"] Board --> Dino["🦖 DinosaurController"] Board --> Power["🔋 DinosaurPower"] Board --> LocalAudio["💾 DinosaurAudio"] Audio --> Codec Audio --> Engine["🧠 AFE AudioEngine"] Protocol --> WS["🔌 WebSocket"] Protocol --> MQ["📡 MQTT + UDP"] MCP --> Dino LocalAudio --> Audio Dino --> Servos["🤖 五路舵机"]

2 构建时如何选中这块板

运行固件之前，构建系统必须保证只编译一个板型。wzh_dinosaur 的选择链路：

1config.json → 2build.py → 3Kconfig → 4CMakeLists → 5*.cc 编译 → 6create_board() 
python3 scripts/build.py wzh_dinosaur --name wzh-dinosaur
要点：
  • 目录名 wzh_dinosaur（下划线），构建名 wzh-dinosaur（连字符）
  • 芯片目标：ESP32-S3
  • DECLARE_BOARD(WzhDinosaur) 生成唯一工厂函数
  • ESP32-S3 主 Flash ≠ W25Q256 恐龙声音存储，二者是不同硬件

4 ESP32-S3 上电后的完整启动顺序

4.1 进入 app_main

ESP-IDF 启动 FreeRTOS 后调用 app_main()，按照严格的 5 步序列启动：

1nvs_flash_init() → 2擦除恢复 → 3GetInstance() → 4Initialize() → 5Run() 🔄 永不返回

4.3 WzhDinosaur 构造顺序

① I2C 总线

创建 ES8311 使用的 I2C0

② 电源

拉高 GPIO7 锁存，初始化 ADC，启动电源任务

③ 离线音频

初始化 W25Q256 SPI，读取 PNDA TOC

④ 舵机控制器

开启电源，配置 LEDC PWM，启动动作任务

⑤ MCP 注册

注册 3 个恐龙专用 MCP 工具

⑥ GPIO 回调

单击/双击回调，投递无声 discover 动作

5 主事件循环

Application::Run() 把主任务优先级设为 10，永久等待 Event Group：

事件驱动模型
flowchart LR A["🌐 网络回调"] --> E["⚡ Event Group"] B["🎤 音频任务"] --> E C["⏰ 定时器"] --> E D["🔘 按键"] --> E E --> F["🔔 唤醒主循环"] F --> G["📋 主任务串行处理"]

核心设计原则：

Application::Schedule() 是跨任务修改状态的主要入口——回调不应直接修改状态，而是把函数放入 main_tasks_ 队列，再唤醒主循环执行。

6 设备状态机

状态转换图
stateDiagram-v2 [*] --> unknown unknown --> starting starting --> wifi_configuring: 没有凭据或超时 wifi_configuring --> activating: 配网成功 starting --> activating: Wi-Fi 直接连接 activating --> idle: 激活完成 idle --> connecting: 按键或唤醒词 connecting --> listening: 语音通道打开 listening --> speaking: 服务端 TTS speaking --> listening: 自动对话继续 speaking --> idle: 手动模式结束 listening --> idle: 停止/关闭会话

7 Wi-Fi 与配网流程

Wi-Fi 事件消费链路
flowchart TD A["📡 WifiManager"] --> B["WifiBoard::OnNetworkEvent"] B --> C["🦖 WzhDinosaur 包装"] C --> D["设置 online/offline"] C --> E["转发给 Application"] E --> F["更新公共状态"] E --> G["激活/初始化协议"] E --> H["断网关闭会话"]
⚠️ 恐龙的 online_ 表示 Wi-Fi 已连接，不表示语音会话已打开。语音通道在用户开始对话时才建立。

8 激活、资源、OTA 和协议

1创建 Ota 对象 → 2检查资源分区 → 3查询固件版本 → 4执行 OTA → 5创建协议 → 6进入 idle ✅
协议选择规则：MQTT 参数优先 → WebSocket 参数其次 → MQTT 默认路径兜底
注意区分两类"下载"：DinosaurAudio 只读 W25Q256，不下载不更新；XiaoZhi 核心仍保留 assets 更新和 OTA。

9 两种服务端传输方式

单连接模式 — 一条连接同时传输：

  • 文本 JSON 控制消息
  • 二进制 Opus 音频包

打开通道时发送 hello 声明协议版本、MCP 能力、音频格式。

双通道模式：

  • MQTT：会话控制、JSON 消息、MCP、STT/TTS 状态
  • UDP：实时 Opus 音频，AES-CTR 加解密

UDP 通过时间戳和序列号检查重复、乱序或丢包。

上层不关心底层实现，统一接口：

  • OpenAudioChannel() / CloseAudioChannel()
  • SendAudio()
  • SendStartListening() / SendStopListening()
  • SendAbortSpeaking()
  • SendMcpMessage()

10 音频系统怎样运行

10.3 用户语音上行

语音上行流水线
flowchart LR Mic["🎙️ 麦克风"] --> ES["ES8311\n24 kHz"] ES --> Input["audio_input"] Input --> Resample["⬇ 16 kHz"] Resample --> AFE["🧠 AFE/VAD/AEC"] AFE --> EQ["📦 编码队列"] EQ --> Opus["🗜️ opus_codec"] Opus --> SQ["📤 发送队列"] SQ --> Main["⚙️ 主循环"] Main --> Net["🌐 网络发送"] Net --> Server["☁️ ASR/LLM"]

14 大模型情绪如何变成恐龙动作

服务端发来 {"type":"llm","emotion":"happy"}，链路：

llm.emotion→ Display::SetEmotion→ HandleLlmEmotion→ EmotionToAction→ action_queue_→ 🤖 舵机动作

大模型通过 self.dinosaur.react_to_user_emotion 工具主动调用，参数：

happy / loving / sad / angry / surprised / thinking / neutral

loving, grateful🥰 affection
sad, crying, tired😴 sleepy
angry, confident😤 proud
surprised, fearful😲 startled
thinking, curious🔍 discover
neutral / 未知👂 listen

🦎

队列规则：

  • 容量为 4 的 action_queue_
  • 1.2 秒内重复动作合并
  • 队列满时丢弃最旧，保留最新意图
  • 20 ms 插值步长 + SmoothStep 平滑
  • 随机左右镜像，减少机械重复
  • 空闲时五关节正弦摆动形成"呼吸"效果 🫁

16 在线和离线模式切换

🟢 在线模式

  • Wi-Fi Connected → online=true
  • 先做 listen 动作
  • 停止离线随机动作
  • 不播放 W25Q256 声音
  • 接收 llm.emotion + MCP

🟡 离线模式

  • Wi-Fi Disconnected → online=false
  • 做 discover + 本地声音
  • 继续空闲呼吸动作
  • 7～16 秒随机动作
  • 从 W25Q256 选择声音
离线模式不是另一套 app_main——XiaoZhi 主循环、AudioService 和板级任务仍然运行，只是没有服务端语音会话。

17 W25Q256 离线声音链路

离线声音播放流程
flowchart LR Action["🎬 离线动作"] --> Select["📂 选择声音"] Select --> Queue["📋 dino_audio 队列"] Queue --> SPI["💾 分块读 W25Q256"] SPI --> OGG["📦 OggDemuxer"] OGG --> Decode["🔊 解码队列"] Decode --> Output["🔉 ES8311 扬声器"]

DinosaurAudio 复用 AudioService，不与在线 TTS 产生驱动冲突。

18 电源与电池任务

dino_power 任务职责：

  • GPIO7 维持电源锁存
  • 每 20ms 读取模拟电源键
  • 长按 1.5s → 拉低 GPIO7 关机
  • 每 5s 采样电池 ADC ×32 取平均
  • 3.2～4.2V → 0～100% 线性映射
无充电检测脚 → charging=false, discharging=true 固定报告。电量只是粗略估算。

24 当前实现边界

⚙️ 编译通过 ≠ 舵机方向正确，需真机校准
💾 W25Q256 必须有正确格式的 PNDA TOC
🧠 设备端不做 ASR/大模型，离线只有预置声音
🎭 用户情绪由服务端文本模型判断
🖥️ 无屏幕但有 Display 对象——情绪适配器
🔗 在线/Wi-Fi/协议/对话 是四个不同概念
