## 当前形态

当前版本是一套无屏幕、五舵机、支持本地默认音频，并能根据用户情绪做出身体动作的恐龙固件。

它没有把旧工程的 `main` 目录整体复制进 XiaoZhi。旧工程中的硬件能力被放进独立板级模块，避免与 XiaoZhi 的入口、Wi-Fi、音频任务和协议实现冲突。

当前包含：

- ES8311 麦克风输入和扬声器输出。
- 共享外部Flash目录与默认音频，Audio Hub绑定、清单同步及音频更新。
- 头部转动、颈部俯仰、颈部侧倾、尾巴上下和尾巴左右五路舵机。
- 电源锁存、电池电压检测和长按关机。
- IO5 四路 R-2R 触摸检测及触摸动作反馈。
- 在线对话及大模型情绪动作。
- 离线自主动作及本地声音。

当前不包含：

- 固定 Wi-Fi 名称和密码。
- HTTP 文件上传服务。
- 旧工程自己的 `app_main` 和独立 I2S 播放任务。

## 开机后的行为

设备开机后依次初始化 I2C、ES8311、电源检测、W25Q256 和五路舵机。

舵机回到默认位置后，恐龙先执行一次 `discover` 探索动作。空闲时以板级默认姿态为中心做缓慢呼吸，呼吸结束会在中位自然停顿；偶尔短暂观察后也会回中。

按键行为：

- GPIO0 单击：配网状态下进入配网，正常状态下切换对话状态。
- GPIO0 双击：停止/恢复宠物活动。
- 模拟电源键长按约 1.5 秒：关闭电源锁存。

触摸行为：IO5 每 20 ms 连续采样 3 次并取中值，连续 5 个解码结果一致后才确认；
单点触摸提交 `affection`，两点及以上组合触摸提交 `happy`。触摸回调只向有界动作
队列投递，不在电源任务内直接运行舵机动作。在线时不叠加本地声音，离线时允许播放
动作对应的本地声音。

## 离线模式

设备没有进行语音交互时进入离线模式。即使 Wi-Fi 已连接，只要设备处于 `idle` 待机、没有听用户说话或播放回复，也按离线模式运行。Wi-Fi 断开和配网状态同样属于离线模式。

离线状态下，恐龙保持幅度清晰但周期缓慢的呼吸动作，并沿用原有触发节奏：前一个完整动作结束约 5～13 秒后再随机执行下一个动作。可选动作包括：

- `discover`：探索和观察。
- `affection`：亲近和撒娇。
- `happy`：开心摆动。
- `proud`：昂头和展示。
- `eat`：重复进食动作。
- `listen`：左右倾听。
- `sleepy`：低头困倦。

离线声音直接从 W25Q256 中已有的 `PNDA` TOC 读取。固件支持现有版本 1 和版本 2 的 TOC，并通过 XiaoZhi 的音频解码队列播放 OGG/Opus 数据，不会联网下载音频。

自主模式先选择实际 Flash 音频，再根据文件名和时长选择动作；明确指定动作时仍优先
选择与该动作匹配的声音。匹配关键词包括：

| 动作 | 优先匹配的名称 |
| --- | --- |
| eat | 吃、咀嚼、eat、chew |
| listen | 脚步、虫鸣、鸟叫、下雨、流水、step、foot、rain |
| sleepy | 入睡、困、sleep |
| startled | 警觉、受惊、startle、alert |
| happy | 雀跃、开心、宝宝、嘤嘤、happy、joy |
| affection | 亲近、撒娇、安慰、comfort、nuzzle、cat |
| discover | 发现、探索、好奇，或不超过约 1.7 秒的短声 |
| proud | 叫声、咆哮、成年、威风、call、roar、adult，或较长声音 |

音频进入播放任务后，动作线程最多等待 300 ms 确认目标文件已真正开始，再同步起动作。
完整动作库现有 24 套，1～4.2 秒声音从 24 套 Flash 专属紧凑编舞中选对应类别，另有
7 套怒吼变体，共 55 套声音表演。所有“叫声音效合集 (N)”/怒吼/长啸/咆哮/`roar`
都会按时长进入怒吼库：正面长啸、短吼回应、轻微侧仰、高位扫视或二次回应。每套都
先让颈俯仰明显到达 0～4°，再做有限且平衡的横向细节；不随机镜像、不叠加额外横向
音频偏移，声音包络主要加强仰头和抬尾，避免动作总朝同一侧。
同类完整动作和短声动作都会避开刚播放过的轨迹。长声音使用完整编舞；
声音长于编舞时只会拉长动作，不会为了追赶短音频而加速。实际 PCM 包络继续叠加低频
细节，Flash 表演期间声音越饱满，五轴姿态越舒展，轻声时自然收住。

如果外部 Flash 中没有有效 TOC，恐龙仍会正常做离线动作，但不播放本地声音。

## 在线模式

设备进入 `connecting`、`listening`、`speaking` 或录音测试状态时才进入在线模式。语音录制、ASR、对话和 TTS 继续使用 XiaoZhi 原有流程。

切入在线状态时会停止并清理正在播放或等待播放的 W25Q256 本地声音，避免干扰麦克风或与服务端 TTS 同时占用扬声器。完整身体动作由服务端情绪事件或大模型 MCP 调用驱动；即使没有情绪事件，在线 TTS 的真实输出响度也会自动带动颈部、头部和尾巴。对话结束回到 `idle` 后立即恢复离线自主模式。

设备提供以下 MCP 工具：

- `self.dinosaur.react_to_user_emotion`：根据用户当前情绪执行身体动作。
- `self.dinosaur.action`：执行指定动作。
- `self.dinosaur.get_mode`：返回当前 `online` 或 `offline` 模式。

设备收到 XiaoZhi 的 `llm.emotion` 后也会自动执行对应动作。

## 情绪如何由大模型感知

当前的主要判断链路是：

1. 用户语音上传到服务端并转换为文字。
2. 大模型结合当前文字、前后文和对话状态判断用户情绪。
3. 用户表现出明显情绪时，大模型调用 `self.dinosaur.react_to_user_emotion`。
4. 设备把情绪转换成五路舵机动作。

设备端没有用少量关键词假装完成完整的情绪识别。仅靠文字能够判断大部分语义情绪，但无法可靠区分反讽、哭腔、紧张语速或低落音色。作为兜底，设备会对用户的转写文本做一次轻量关键词匹配（如“满分/太棒/好困/吓死”），让明显的情绪也能在服务端情绪链路缺省时立刻触发动作；同时 `llm.emotion=neutral` 这种界面复位信号会被忽略，避免说完话后恐龙莫名做一个“听”动作。

如果后续希望利用声学情绪，推荐在服务端增加语音情绪模型，提取音高、能量、语速和声音类别，将分析结果连同 ASR 文本一起提供给大模型。设备端协议和动作接口不需要因此改变。

## 当前动作实现

`stories-v4` 新增 `affection-check-in`、`listen-confirm`、`roar-soft-answer`、
`roar-crown-arc`。短吼候选增加到三种，长吼有独立高位弧线；仍先正面仰头。
随机幅度和镜像解析后先夹紧物理目标再插值，避免在超范围的虚拟目标处空等。
生命微动窗口改为两端斜率为零，短于 900 ms 的帧按时长减弱微动；原触发间隔不变。

2026-09-13 用户确认五轴实机映射与 config.h 一致。新增高低巡视 `discover-canopy`、
探身招呼 `happy-invite`、贴地取食 `eat-graze`，均为全轴同步的慢速故事。
取食正面落点为 IO17=180，头/颈左右保持 90；深低头时平滑减弱声音抬头叠加，
180 度不再被声音拉起。显式 0/180 关键帧不受随机缩幅影响。触发间隔与旧动作不变。

怒吼版本标记为 `roar-onset-v3`。全部怒吼首帧直接正面仰头，默认姿态下约 900 ms
到达 IO17=0、IO16=90、IO15=90；保持统一限速，长声只拉伸后续段落，回中单独计时。
后续侧仰通过头部反向补偿视线、尾巴反向配重表现身体变化。`Roar pose` 日志记录
最终下发角度。新增 `self.dinosaur.test_servo(gpio)` 用于用户显式要求的单轴装配核对，
支持 17/16/15/8/18，小范围往返、无声音和生命偏移、结束回默认。
方向已由用户确认；本次新增组合动作的机械干涉、电流和听感同步仍需刷机观察。

当前使用关键帧编舞引擎，8 类动作共有 24 套完整编舞（discover/happy/affection 各四套，eat/listen 各三套，其他类别各两套）和 24 套 Flash 短声编舞（每类三套）。第三批短声动作参考旧工程的仰望追踪、害羞贴近、空间画圆、威严守望、取食回看、高空聆听、低伏躲避和绕身入睡，但改为五轴同步起停。旧工程只对尾上下使用反向内部角度，移植时统一按 `实际角度 = 180 - 旧数据角度` 换算：

- discover
- affection
- happy
- proud
- eat
- listen
- startled
- sleepy

借鉴旧 dinosaur 工程的动作节奏，但按本板角度语义重新编舞：

- **KEEP 保持轴**：关键帧中 `kKeep` 只表示该轴维持上一姿态；同一关键帧中所有需要变化的轴仍同步起停。
- **同步协调**：同一关键帧内需要变化的五轴共用一条插值进度，同步开始并同步到达，不制造头、颈、尾的人工启动延迟。
- **舒缓限速**：每一个发生位移的关键帧至少运行 420 ms，并根据最大关节行程把最快轴平均速度限制在约 80 度/秒以内；普通动作恢复原有三次 SmoothStep，`kFastOut` 保留较明显但仍柔和的提前到位感。
- **随机变奏**：每次表演随机镜像方向、幅度（0.92~1.10）和节奏（完整动作 0.88~1.00、短声动作 0.94~1.02，数值越小越慢）；随机方向同侧最多连续两次，避免长时间偏向一边。
- **动作中生命感**：关键帧插值过程中叠加肉眼可见但周期很慢的呼吸和重心变化，避免到达姿态后像机械定格。
- **连续轨迹**：连续同向的 `kSmooth` 关键帧使用夹紧的单调 Hermite 切线穿过中间姿态，不再“每帧刹停再起步”；反向、定格、首尾仍会自然减速，轨迹不超出相邻角度。
- **中位慢呼吸**：约 12 秒一轮，缓慢吸气和呼气后在默认中位停顿约 4 秒；观察偏姿仅保持约 3~5 秒，之后回中约 9~15 秒。
- **待机生命脉冲**：静止时按原有约 5~14 秒间隔插入观察、尾摆、嗅闻、精神一振、好奇侧头、友好招呼、二次确认或全身舒展；相邻两次不重复，每一段仍受同步和慢速约束。
- **Flash 专属表演**：8 类动作各有三套短音频紧凑编舞；较长 Flash 声音继续配完整动作，并按音频时长向慢方向拉伸。
- **防复读**：每个行为族分别记住上一次完整剪辑和短声剪辑；同类动作连续触发时会换一条轨迹。
- **无偏置合成**：基础姿态与声音偏移分开保存，生命微动在关键帧落点归零；镜像只处理本帧新目标，不会二次翻转 `kKeep` 轴。
- 非短声完整动作使用 500 ms 注意姿态起手；短声和怒吼直接随音频起步。短声/怒吼使用 760 ms、完整动作使用 820 ms 的回中收势，实际移动仍会被统一限速自动拉长。
- 离线完整动作沿用原有约 5~13 秒间隔；明确动作结束后的自主等待约 5~10 秒。
- 动作队列只保留最新的一个待执行意图，同类动作仅在 1.2 秒内合并，避免同一次状态更新重复触发。
- 音频随动统一读取扬声器实际 PCM 包络：在线 TTS、Flash 本地声音和系统提示音都会让五轴同步响应；响度控制整体姿态和低频摆动幅度，重音形成柔和抬头，同一段声音保持连续观察方向。

角度均为本板舵机直接角度：`neck_tilt` 0=最高/仰、180=最低/俯；`neck_lean` 和 `head_turn` 0=右、180=左；`tail_lr` 方向相反，0=左、180=右；`tail_ud` 55=最低、180=最高。增加动作时应先根据真机方向和机械限位校准角度。

## 真机待验证项

软件构建成功不能代替硬件验证。首次烧录后需要依次检查：

1. 五路舵机的实际方向。
2. 每个动作是否超过机械限位或发生结构碰撞。
3. 舵机电源开启后是否造成 ESP32-S3 掉电或复位。
4. ES8311 麦克风录音和扬声器播放。
5. W25Q256 中已有 TOC、地址和默认音频是否与固件读取格式一致。
6. 电池分压计算和实际电量显示。
7. 长按关机和电源锁存逻辑。
8. 在线 TTS 与动作是否同步，以及切换在线/离线时是否符合预期。
9. IO5 在释放、SW1～SW4 单点和组合触摸时是否稳定落入对应的 16 档电压区间。

## 感应和动作保护更新

IO41 人体感应及 I2C1 的 SC7A20H 现已接入；离线动作关键词通过现有 MultiNet/AFE
在 idle 本地执行。新增欠压、芯片温度与通电预算保护；动作/脉冲结束释放 PWM 和舵机
电源，安静待机不再持续输出呼吸角度；声音播放期间仍保留 PCM 随动。
正常关机由动作任务回默认姿态并释放，严重欠压直接断电。详细行为与硬件限制见
[共享说明](../../../docs/wzh_sensing_and_protection.md)。
