## 音频通路

ES8311 内部参考由 `no_dac_ref=false` / ADCL + DACR 提供。
输入按交错的麦克风 M、DAC 参考 R 采集，重采样时两声道一起变为 16 kHz，送入同一个 FD AFE。
使用 `AFE_TYPE_FD`、`AEC_MODE_FD_LOW_COST`、AGGR 残余回声抑制和 VAD_MODE_3。
WakeNet 和本地 MultiNet 仍复用原来的 AFE，不新增 I2S 驱动、解码器或播放任务。

共享 IN_OUT codec 按两个物理声道打开。逻辑扬声器接口保持单声道：写入时按每次最多
240 个采样，将每个 PCM 样本复制到两个 I2S 时隙，避免只写单声道造成时长/音调错误。
普通版和其他板卡默认仍使用原单声道采集/播放。采集错误返回无有效数据，不上传未填充缓冲。

## 本地打断及前缀

正在播报时保持收音和本地 AEC，但不直接上传此时的麦克风音频。
最多保留 12 个已经消回声的 Opus 包，约 720 ms；队列始终有界。
检测到本轮 DAC 参考 RMS 超过 8 后允许判定；音量为 0 时不要求参考有能量。
随后先保留 240 ms 的稳定期，再要求持续 180 ms 同时满足 VAD 和能量条件。
能量门槛为 `max(260, 3 × 自适应噪声 RMS)`，单位是 int16 PCM RMS。
这些是测试初值，不能当作已装机标定值或真实打断延迟承诺。

主任务处理确认事件：

1. 检查检测 token、会话状态、停止标志和网络通道，拒绝已过期的确认。
2. 关闭旧回复接收入口并推进交互代次，清除旧早期音频和待播放 PCM。
3. 本地取消先于网络 abort，不等待服务器停播。
4. 使用原有 `abort` 与 `listen/start/auto` 消息继续收音，前缀按顺序先发，再接实时录音。
5. 不重启 AFE、不重新预热麦克风、不插入提示音，避免截掉用户开头的字。

捕获代次会拒绝停止/重启前尚在编码的旧录音。正常播报结束后丢弃监测缓存并返回普通
自动聆听；服务器先发 stop、扬声器仍有尾音时继续保持本地打断监测。
唤醒词在同一批事件中优先于普通人声确认，普通双击退出和停止/维护仍保持优先。
硬件 DMA 已提交的声音会有有限尾声，软件队列清空不等于物理扬声器零延迟静音。

## 服务器边界

使用现有 auto 聆听协议，不要求新增云端接口，也没有开启服务器 AEC。
本地打断后，在下一条非空 STT 转写到达之前拒绝 TTS start/stop/sentence、二进制音频和
旧 LLM 情绪；已排队的旧代次任务也不会清除新回复的首包。
标准 WebSocket 和 MQTT/UDP 共用同一套逻辑。

当前协议没有逐回复 ID，因此依赖服务器保持“新 STT 在新 TTS 前”的原有消息顺序。
不发 STT 或任意重排旧/新回复的服务器不属于本测试版的兼容承诺；这类场景仍可用唤醒词
或双击退出。MCP 等独立设备控制消息不按语音回复屏蔽。

## 装机测试顺序

1. 先用原音量播放固定语句，核对声音完整、无变速和无异常失真。
2. 从 USB 日志查看 `MR capture: mic RMS=..., DAC reference RMS=...`。
   安静不播放时参考应接近安静；播报时参考应随音频变化；仅对麦克风说话时主要是麦克风变化。
3. 不说话让其连续播报，包含本地提示音、故事、音乐和正常舵机动作，检查不自行打断。
4. 播报中直接说“等一下，我想问另一个问题”，检查停旧回答、保留首字、正确回答新问题。
5. 分别测试短句、轻声/正常音量、不同距离、不同扬声器音量和多人/电视背景。
6. 连续打断、短回复尾声打断、唤醒词打断、双击退出、断网重连，检查无旧语音/情绪复活。
7. 再验证触摸、离线口令、Flash 音效、三轴动作和供电；不改变原机械限位。

出现自打断、听不清、参考一直为零或播放异常时，使用保留的普通优化版回退。
