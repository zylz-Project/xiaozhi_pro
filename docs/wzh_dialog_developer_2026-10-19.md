## 对话动作

回复句子通过既有的 `SetChatMessage("assistant", ...)` 进入板级控制器，在本地形成一个有限的表达风格提示，再由扬声器实际 PCM 的能量、重音与停顿驱动动作。网络/界面回调只更新轻量状态，所有插值仍由运动任务执行。

| 句子风格 | 例子 | 表现 |
|---|---|---|
| 问候 | 你好、我在呢、欢迎 | 关注用户、单爪招呼或头尾展开 |
| 开心 | 太棒了、恭喜、成功了 | 更活泼的交替回应与欢迎，略快的节奏 |
| 安慰 | 难过、别担心、慢慢来 | 放慢并降低强度，以停留和温和回应为主 |
| 提问 | 问号、为什么、猜一猜 | 探看、停住、换侧回应 |
| 故事 | 从前、有一天、竹林里 | 分段观察、伸展和换边 |
| 晚安 | 晚安、好梦、休息一下 | 更缓、更小的收拢表达 |
| 普通交流 | 其他句子 | 原有六种空间表达组合轮换 |

这是轻量的句子风格判断，不是额外调用一个语义模型，也不承诺逐字动作对齐。服务器句子通知可能早于排队语音真正播出，因此风格是句级近似提示；动作起落以实际 PCM 为依据。回复内容不会被当成停止、关机、擦除等控制指令执行。

真实重音经过至少 360 ms 的间隔控制和衰减，再加强正在表达的关节；普通停顿不会每 60 ms 重启一套姿态。持续无声后逐渐收势，语音尾部在云端 `stop` 通知之后仍跟随尚在播放的 PCM，退出会话则清除旧语句状态。

大熊猫保留独立左右爪，小熊猫保留头尾上下/左右呼应，恐龙使用五轴表达。阻尼、速度限制、机械夹紧和原有保护继续生效；不把每个音节峰值直接写成舵机角度。

## 安静归中

本轮修正了“退出对话后停在断开前姿态”的路径。没有本地配对音频、实际语音或正在执行的明确动作时，从**最后输出到舵机的命令姿态**平滑归中，包含语音叠加造成的偏移，不再只使用旧剪辑的逻辑姿态。

| 产品 | 默认姿态，按本机轴序 |
|---|---|
| 大熊猫 | 头/左爪/右爪：90 / 90 / 90 |
| 小熊猫 | 头/尾左右/尾上下：90 / 90 / 150 |
| 恐龙 | 颈俯仰/颈侧倾/头转向/尾上下/尾左右：70 / 90 / 90 / 90 / 90 |

归中使用有界平滑轨迹，到位后稳定 450 ms 再卸力，随后不反复上电。停止/休息完成有限归中后保持等待；欠压、跌落、过热、维护及关机保护仍立即优先，不能为了归中强行带电。进入连接/倾听阶段不再额外排入一段无声倾听表演。正常模式下空闲约2秒后的音画回应仍保留。

本机没有舵机位置反馈；这里的姿态是软件输出目标。机构断电后的实际保持、负载下到位时间仍需装机确认。

## 开发者模式

仍访问设备管理页 `http://192.168.4.1:8080/`，右上角点“开发者模式”，按用户要求输入密码 **`1`**。

- 登录后由设备签发随机令牌，30 分钟有效。调试写接口在服务端检查 `X-Developer-Token`，只修改网页显示无法绕过检查。
- 令牌只保留在当前页面内存；刷新页面需要重新进入，退出会使令牌失效。密码按当前展示需求固定为 1。
- 主界面保留会话状态、真实 Flash 音频库和手动 Hub；调用接口说明折叠到开发者区。

| 功能 | 行为 |
|---|---|
| 扬声器音量 | 0～100，点击应用后保存；0 为静音，重启仍保留 |
| 随机展示一段 | 从现有动物音选择，使用该文件的配套动作，不选择长环境音 |
| 停止并归中 | 停止当前本地声音、取消旧动作并归中；对话中拒绝，避免影响云端回复 |
| 诊断导出 | 导出设备状态和实际音频目录 JSON；含构建时间、内存、网络、会话及 Flash 状态，不导出 Hub token 或开发者令牌 |
| 实时音频观察 | 显示 PCM 能量；区分对话收音、唤醒待命与播放处理，不再只按 Speaking/Listening 推断 |
| 外置音频 Flash 擦除 | 需要额外输入 `ERASE`，异步执行并显示最终结果 |

## Flash 擦除边界

只擦除**外置音频 Flash 的全部用户音频数据和目录**，不擦内部固件、Wi-Fi 配置或小智绑定。进入开发者模式本身不会擦除，也不会自动重新下载音频。

服务器检查令牌及确认文字，拒绝对话、写入、Hub 工作或电量不高于 15% 且未报告充电的状态；主任务在真正开始前再次检查空闲状态。取得维护占用后禁止新的对话与 Hub 任务，停止本地播放，等待读取任务退出，再由独立任务擦除，HTTP 和主循环不等待整片操作。

若读取任务 2 秒内没有退出，或任务无法创建，不执行擦除并恢复状态。开始物理擦除之后不能取消，关闭页面或退出开发者模式不会中断该操作，应持续供电。擦除失败可能已删除一部分数据，因此停用旧的内存目录，需重试擦除后重新导入，不会把旧目录假装成完整可播放。

成功后刷新页面目录，清除 Hub 的本地 revision 与旧差异缓存，保留 Hub 绑定信息。重新导入仍需用户手动检查和更新。

## 同步修正

- 正常 TTS `stop` 不再提前删除同一轮尚待主任务接收的首包；用户取消和失效会话仍清理。
- 当前本地音频名称从播放器持有的文件身份读取，避免栈对象失效和目录下标变化带来的错误。
- “停止试听”在主任务重新检查播放来源，不会在小智回复时复位共享解码器。
- HTTP 在 1024 字节上限内有限时地读取完整 JSON，验证对象、整数音量、音频下标及更新选择。
- Hub 检查与更新分别显示结果；运行时采用不定进度动画，禁用重复更新与修改选择。

现有 Hub 下载仍依赖服务端清单下标，完整内容指纹和不可变版本下载尚未实现；检查与更新期间应保持服务端音频清单稳定。[之前的复查报告](review/wzh_latest_changes_2026-10-19.md)中的这一项与“同大小内容校验”限制仍保留，本轮没有改动服务端协议。
