# 互动声音改为使用已有外置 Flash 音频

后续更新：三款加入独立触点变化、专用互动与连贯 Flash 播放；当前行为及最新镜像以[成品互动体验说明](wzh_product_experience_2026-10-16.md)为准。

按用户要求，爬爬熊猫、恐龙、摇尾小熊猫的触摸与姿态互动，统一使用板上外置音频 Flash 中已有的 OGG/Opus 文件。
已撤下上一版新增的 16 个合成短音、生成脚本及 app 内嵌入口。没有写入、擦除或重新生成设备的外置音频库。
系统提示音、在线 TTS 和语音识别模型继续使用原来的资源链路。

## 选声与回应

| 互动 | 优先匹配的现有文件名含义 |
| --- | --- |
| SW1、持续按住 | 撒娇、亲近、安慰、呼噜 |
| SW2、连续轻触、组合触摸 | 开心、雀跃、嘤嘤、宝宝 |
| SW3、长按后释放、姿态稳定 | 好奇、发现、探索、叫声 |
| SW4 | 亲近、开心 |
| 拿起估计 | 亲近、好奇 |
| 摇晃、翻面估计 | 警觉、受惊、惊讶；其次好奇、叫声 |

选择基于实际目录的文件名，兼容中文及常见英文命名，不假定条目顺序。
同分素材中优先使用不超过 2.5 秒的文件，并在同分候选中随机挑选；按完整原文件解码，不预先裁剪、变速或合成声音；停止、休息、安静或进入对话仍可取消当前播放。
环境音不参与触摸和姿态回应。进食、入睡文件降低选择优先级，仍可用于原有对应动作。

有多个有效动物声音时，下一次互动跳过上一条文件，再按本次互动匹配程度选声；即使上一条是唯一语义匹配，也会换用其他动物声音。
如果目录里只有一条动物声音，仍会重复使用这一条；软件无法把单条原始素材变成多个不同录音。
目录为空、Flash 不可用或没有有效动物声音时，只给动作回应，不播放合成替代音。后续 Audio Hub 正常填充目录后可使用新文件。

四触点分流、两款熊猫的独立短动作、拿起/摇晃识别改进、SC7A20H 重试诊断及所有保护均保留。
明确互动的声音启动间隔下限仍为 650ms，扬声器忙时不叠加新声音；原文件较长时，新动作保留当前声音，不能把 650ms 理解为每次都能连续发声。
普通表演保留 12 秒声音预算。温和窗口允许互动声音；安静时无声，停止/休息和保护继续限制动作。

## 播放与对话

选中的文件名、数据偏移和时长跟随有界播放请求一起保存，避免 Audio Hub 删除目录条目后索引移动，导致排队请求播错文件。
声音由工作任务分块读取外置 Flash，经同一 OGG/Opus 与 AudioService/ES8311 链路输出。
进入建立会话、录音或在线回答时拒绝本地播放；排队请求开始播放前再次检查，取消代次保留。

## 实机确认

触摸后日志应显示实际选中的外置文件，例如：

```text
PandaMotion: Interaction=touch1 accepted
WzhAudioPlayer: Interaction=touch1 external Flash sound: 熊猫撒娇声音
WzhAudioPlayer: Playing offline sound: 熊猫撒娇声音
```

这里的文件名仅为示例，实际以设备目录为准。需要确认目录内容时，可通过原有 `sound_list` 工具查看。
当前无法从本地源码直接读取样机 Flash 的目录，因此没有虚构具体已有素材的数量和时长。
