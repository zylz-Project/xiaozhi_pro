# WZH 本地管理页、手动音频更新与小智对话检查

状态：方案及界面原型，未接入实体设备；本次未修改固件源码或重新打包。日期：2026-10-19。

> 同日更新：体验版已接入固件——设备在 STA 联网后自建管理热点，页面与接口在 `192.168.4.1:8080`，Audio Hub 改为手动检查/更新。使用说明与限制见 [设备热点管理页体验版](wzh_console_firmware_2026-10-19.md)。主机测试 157 项通过，三款固件已重新打包。仍待实机验证热点/STA 并发、配网切换、Hub 更新和断电恢复。

## 目标

三款产品继续使用小智原生云端对话。开机、联网、打开管理页都不自动连接 Audio Hub。用户在网页主动检查、选择、更新时，才访问 Audio Hub。已写入外置 Flash 的录音保留，正常使用不依赖音频服务器。

界面见 [可交互原型](wzh_console_prototype_2026-10-19.html)。原型目录来自本地音频包，所有设备状态与控制结果均为示例，不代表设备 Flash 实读或已经执行操作。

## 代码复查结果

检查的是当前工作区源码，包含最新的双击进入提示音播放完再收音逻辑。重新运行全部主机测试：157 项通过。补充生产代码提取回放发现下列未被现有测试覆盖的边界；其中上行发送和 TTS 首包两项已在随后修复并加入回放，其余仍待实施。主机结果不代表实机发生频率。

| 优先级 | 发现 | 证据与影响 | 处理方向 |
|---|---|---|---|
| P1 | 退出标志没有覆盖语音上行发送 | `Application::Run()` 的 SEND_AUDIO 分支直接调用 SendAudio；StopInteraction 的清理还在 Schedule 队列中时，队列语音仍可发送。提取生产分支回放，stopped=true 时仍发出 1 包。 | 发送前检查会话有效性与实际收音许可；停止时清空编码/发送队列；给在途编码任务增加录音代次，避免旧编码结果进入新会话。 |
| P1 | TTS 开始通知与首个音频包存在任务时序窗口 | TTS start 通过 Schedule 切换 Speaking，但 OnIncomingAudio 只接受 Speaking。回放 start 后立即送入音频，主任务处理前后保留包数均为 0。 | 在网络接收边界按原连接的消息顺序分发 start/音频/stop，设置有界的首包暂存与会话失效规则；先完成主任务中的必要复位，再放行音频。不能简单把 Listening 的所有音频都放入播放队列。 |
| P1 | Audio Hub 仍然自动联网 | Start 设置 sync_now=true；Task 自动注册/激活轮询、60 秒心跳、每小时同步，失败后自动重试。 | 改为用户请求驱动；开机只加载本地配置与缓存状态，等待明确任务。 |
| P1 | 现有整库同步会删除本地独有录音 | SyncOnce 在下载后遍历本地目录并 DeleteFile，删除远端清单中不存在的项目。 | 网页更新默认只新增/替换选中的文件，保留本地独有文件；删除必须是独立明确操作。 |
| P2 | 现有 MCP 音频播放在云端会话中被拒绝 | sound_play 最终调用 QueueFile，该函数拒绝 Connecting、Listening、Speaking。列出目录不等于云端小智能在对话中播放录音。 | 网页默认遵守忙状态；小智明确请求叫声时增加单个待执行音频任务，等待云端播放结束、暂停上行，播放后恢复原会话。云端新回复、退出或关机可取消本地任务。 |

相关位置：`main/application.cc` 的 Run、OnIncomingAudio、OnIncomingJson、StopInteraction；`main/audio/audio_service.cc` 的 OpusCodecTask、ResetDecoder；`main/boards/common/wzh/wzh_audio_hub.cc` 的 Start、Task、SyncOnce；`wzh_audio_player.cc` 的 QueueFile。

已核对的正确部分：三板双击调用原生 Application，进入通过原生 Protocol::OpenAudioChannel；根据既有配置使用 MQTT/UDP 或 WebSocket、Opus；没有导入参考例程的 chat/realtime_ws 对话链路。当前非实时双击进入已等待提示音完成再收音；实时 AEC 与原有唤醒路径保留原策略。旧 PCM、提示音生产者与排队回调已有代次过滤，但不能用这点推断编码上行和首包边界也已完整覆盖。

连接中的取消仍受原同步握手调用耗时影响：先记录取消、禁止开始收音，握手返回后关闭。网页应显示“正在取消”，直到实际结束，不能提前显示已经完成。

## Audio Hub 改为按需访问

不能只把 WZH_AUDIO_SYNC_ENABLE 关闭，否则现有 Start 提前返回，网页也无法使用下载客户端。应保留客户端编译能力，移除自动任务行为：

- 开机只读取已有 server/token/revision，不注册、不心跳、不检查清单、不下载。
- 网页状态刷新只读取本机缓存，不触发远端检查。
- 用户点击“连接并检查”才发起一次有超时的检查任务。未绑定时显示现有绑定信息，由用户明确继续；不在后台无限轮询。
- 检查只取得远端清单与差异，不写 Flash、不调用现有整库 SyncOnce。
- 用户选择文件并点击“更新所选”后，冻结本次目录版本与选择集，执行该批任务。
- 重试仅限本次任务且有次数上限；任务完成、失败或取消后不再访问服务器，重启也不自动续传。
- 复用现有 NVS 配置键与绑定信息；新的模式和任务状态有明确默认值，不改变小智云端服务器配置。
- MCP 的 sync_now 不能绕过手动策略启动整库镜像同步；保留状态查询，更新走同一任务入口与选择规则。

## 管理页部署

建议内置轻量网页到 ESP32，连接同一 Wi-Fi 后访问 `http://机器IP:8080`。配网仍用原有门户；管理页服务在配网阶段停止或隔离，避免端口、资源和状态冲突。后续可以增加本地域名，但 IP 入口必须可用。

HTML/CSS/JS 本地内置、压缩交付，无外部字体/CDN。三款共用页面，通过板型与能力信息显示不同关节、触点、Flash 容量。网页不是第二套语音聊天客户端，不实现浏览器麦克风上传或 realtime_ws。

默认同源访问。写操作具有设备侧验证和操作凭据，不把 Hub token 下发给浏览器；页面不保存云端语音内容。HTTP 处理器仅校验、排队、返回任务 ID，网络下载和 Flash 操作使用有界后台任务。

状态约 1 秒刷新一次，任务进度在操作期间适度加快；页面隐藏后暂停高频刷新。日志使用固定长度环形缓冲，不传完整录音，不反复申请大块内存。连接数、任务数和首包缓存均设置上限。

## 页面布局与功能

视觉使用暖白底、森林绿主色、圆角卡片、清晰的中文状态标签。顶部始终显示产品身份、联网情况、小智会话状态、当前播放、固件版本；成功、等待、失败不能只靠颜色表达。手机适配单列，音频表格横向滚动或折叠卡片。

### 总览

- 产品、板型、固件编译信息：用于确认烧录的是哪一个小智镜像。
- Wi-Fi 与信号、小智会话阶段、收音是否实际开启、当前播放来源。
- 电量、电压、温度；传感器不支持或读数失效时显示“未提供”，不填假值。
- 当前动作、关节目标与输出有效性；没有反馈传感器时标为“目标角度”，不能称为实际角度。
- Flash 型号、目录格式、文件数、追加可用空间；Audio Hub 显示“仅手动／未连接”和最近一次检查结果。
- 双击操作说明及显式“进入对话／退出对话”调试按钮。网页按钮投递相同原生入口，不另建协议。

### Flash 音频库

必须从 AudioStore::Snapshot 读取实体机目录，不能用服务端清单或仓库 JSON 冒充。显示名称、类别、大小、时长、稳定标识、校验状态、动作配对状态。原目录缺少准确时长或校验值时明确标记待测，不把估算值展示为已验证。

支持搜索、动物音/环境音筛选、机器试听、配套动作试听、停止、下载单文件备份、导出目录 JSON、复制 MCP 调用参数。操作使用名称/稳定逻辑 ID 与目录版本，避免同步后下标移动播放错文件。

网页与 MCP 共用同一个设备端目录及音频调度器。小智可先 sound_list，再按名称请求播放；网页不会自动赋予当前聊天助手对实体设备的访问能力。导出 JSON 可用于离线分析，实体控制需要实际连通的设备工具。

在线对话时，普通网页试听默认返回“对话中，请先退出”；不自动打断用户。若实现对话内 MCP 叫声，则作为明确的会话子任务处理，并保持原生协议连接；不能强行切到 Idle 或装第二套 I2S。

### 手动音频更新

流程：连接并检查 → 查看远端与本机差异 → 选择新增/替换项目 → 容量预检 → 更新所选 → 校验、提交 → 重新读取 Flash 目录。

差异分为新增、内容变化、相同、待校验、本地独有。仅文件名与字节数相同不能证明内容相同；服务端优先提供 SHA-256、大小、时长、类别、版本。旧接口没有内容指纹时显示“待校验”，允许用户选择重下。

服务端仍使用原 Audio Hub 注册、激活、files、download 接口；不使用参考实时对话服务。检查结果绑定 revision，更新前发现远端版本变化要重新比较，避免按旧数组下标下载到另一文件。产品 ID 必须校验匹配。

默认不选长环境音，不自动删除本地独有文件。更新列表显示每文件字节进度、校验结果、总体完成数、失败原因与取消状态。取消时保留已完成项目、保留当前文件旧版本，不宣称整批原子回滚。

更新前暂停自主表演，获得维护占用，避免自动动作使下载一直判忙。对话与 Flash 写入明确互斥；用户双击对话时取消当前未提交下载，待底层写操作安全结束后进入原生会话。不能在擦写过程中直接复用底层 Flash 总线。

写入继续采用分块接收、大小/格式/内容校验、追加数据后提交目录。必须同时预检目录条目数、追加空间、替换峰值空间；删除条目不代表数据立即回收。NAND 的现有目录提交保护与 NOR 单槽的断电边界不同，NOR 要先解决双目录迁移/备份恢复，不能宣称现有写法完全断电安全。

换成同名但内容不一样的录音，原动作节奏可能失配。精编动作必须匹配录音指纹；新文件先使用根据实际时长和响度驱动的通用动作，并显示“待精细编排”。不把旧时长和旧轨迹盲套到新录音。

### 诊断

显示最近双击识别、原生状态切换、上行/下行包计数、首包接收/播放时间、播放取消、Flash 更新结果。云端连接、待听、正在收音、说话播放尾帧分别显示，方便定位“显示连接但没真正收音”的问题。

主界面避免暴露大量驱动参数；详细内存、ADC 原始值、任务计数放在展开的诊断区域。

## 设备接口建议

| 方法/接口 | 用途 |
|---|---|
| GET /api/status | 本机实时快照，不访问 Hub |
| GET /api/audio | Flash 目录、版本及动作配对状态 |
| GET /api/audio/export | 下载目录 JSON |
| GET /api/audio/file?id=... | 分块备份单文件 |
| POST /api/audio/play | 根据稳定 ID 播放，支持是否配动作 |
| POST /api/audio/stop | 停止本次本地试听 |
| POST /api/chat/start、/stop | 投递原生会话请求，有明确结果状态 |
| POST /api/hub/check | 用户主动检查，返回任务 ID，不写 Flash |
| GET /api/hub/diff | 读取已经完成的检查结果，不发起联网 |
| POST /api/hub/update | 仅更新已选文件，附目录/远端版本 |
| GET /api/jobs/{id} | 本地任务状态与进度 |
| POST /api/jobs/{id}/cancel | 请求安全取消，不承诺瞬间结束 |

一次只接受一项 Flash 写任务；重复请求使用操作 ID 去重。忙时返回明确的冲突状态，断线重开页面后查询现有任务，不重复开始更新。

## 实施顺序与验收

1. 先补齐语音上行取消与 TTS 首包两项回归，再验证双击、提示音、尾音和重开；检查 WebSocket 与 MQTT/UDP 两条原生路径，不导入参考聊天代码。
2. Audio Hub 改手动任务模式，测试开机、联网、反复刷新页面、失败及重启都不自动请求 Hub。以设备/服务器请求记录确认，而不只检查界面文案。
3. 接入只读状态与 Flash 实读目录，再加机器试听、动作配对和 MCP 同源调用。
4. 最后接入检查差异及所选更新，验证断网、版本变动、空间不足、下载取消、CRC/哈希失败、断电恢复和本地独有文件保留。
5. 三板标准构建与包检查；装机验证实际收音/播放/唤醒/VAD/AEC、舵机噪声、长时间展示、低电量及关机优先级。

本轮完成设备热点管理页、只读状态/Flash 实读目录、试听、Audio Hub 手动检查与所选更新，并重新打包三款固件。热点/STA 并发、配网切换和实机写入仍需装机验证；不能把编译通过当作现场验收通过。
