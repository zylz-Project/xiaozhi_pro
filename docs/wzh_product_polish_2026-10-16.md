# 三款 AI 陪伴宠物整机体验优化

日期：2026-10-16。适用：爬爬熊猫、摇尾小熊猫、恐龙。

本轮以家庭连续使用为目标，检查开机、本地互动、语音对话、模式切换、声音维护、停止与关机。此前的大幅动作、每类三套互动变化、连续插值、外置 Flash 录音和静置误触发修正继续保留。本轮没有改动三款身份、引脚、舵机方向、安装限位或持久化键名，也没有连接实物或操作云端账号。

## 一、本轮具体修改

| 场景 | 修改及用户可感知的结果 |
| --- | --- |
| 正常唤醒对话 | 专用 WakeNet 唤醒先停止旧声音并恢复可互动状态，直接沿用小智对话流程；不再额外提交一段带动物声音的探索表演。离线“醒醒”仍可给明确恢复回应。 |
| 连续收到情绪信息 | 情绪请求至少间隔约 1.8 秒；普通情绪、人体回应不会打断正在进行的同级或更高优先级动作。第一段情绪可以接替倾听动作，明确触摸和身体命令仍能及时打断。 |
| 退出对话或断网 | 消耗旧动作代次并清除待处理表情，避免旧会话编舞在本地模式或重连后继续执行。 |
| 安静、休息、停止、恢复、升级 | 清除旧接触、长按、连击及温和状态，不把切换前的接触带到新模式里。后续新触摸照常工作。 |
| 电源键异常 | ADC 读取失败时取消本轮按键与双击计数，必须确认有效松开后重新接收按键；异常本身不计为开关机或对话操作。 |
| 长按关机 | 先结束旧互动，再让健康且正在通电的舵机按原有输出限速返回默认位，最多约 900ms。已经释放或存在保护时保持释放；之后播放原有关机提示并断电。 |
| 动作失败反馈 | 三款新增 `get_pet_status`，报告模式、保护、忙碌和对话状态；原动作工具增加可选 `details=true`，返回请求是否接收及拒绝原因。默认返回保持兼容。 |
| 爬爬熊猫“举手” | 去掉右手规则对通用“举手”的抢先匹配，交给双前肢动作；明确右手命令保留。离线词表仍是原有 12 条。 |
| 后台更新时玩耍 | 开机及最近动作请求后约 30 秒不开始声音同步；舵机动作、本地声音、解码输出或在线对话期间继续避让。进入互动会中止后续下载读取，单次读取超时约 1 秒。 |
| 同名声音更新 | 新数据写到追加区域，完成验证后再替换目录条目；下载或数据校验失败不先删除旧文件，满 32 项目录仍可替换同名条目。 |
| 更新过程响应性 | 网络读取期间不再持有声音目录锁，动作选声和状态查询不用等完整下载；目录计数、类型及 Hub 状态字符串的并发读取也作了保护。 |
| 同步暂停、失败与修复 | 手动同步请求在对话或动作期间保留，失败后退避重试；清单版本相同也会检查并补齐缺失的本地文件，删除失败不前进版本号。 |
| 绑定与协议兼容 | 注册支持 HTTP 200/201、直接令牌和原激活码流程；使用缓存令牌恢复绑定状态，成功绑定后安排首次同步，避免无故等一小时。 |
| 异常响应与清单 | 控制响应最多 8KiB，清单最多 64KiB、32 项；限制单文件大小、整数长度和总容量，拒绝重复名、路径、无效分类和空清单，避免错误返回清掉原有录音。 |
| HTTPS 与日志 | 启用证书包的构建中接入 HTTPS 信任验证；注册错误不打印整份可能带令牌的响应。保留真实输入来源及保护变化日志。 |
| 维护操作 | 删除声音、全片擦除、手动同步及恐龙单舵机测试转为 user-only 工具，从普通模型发现列表中移出。原工具名保留，维护端仍可调用。 |

user-only 是现有 MCP 的工具发现/受众分组，不是新增的家长身份认证。量产维护权限还需要实际服务端配合。本轮没有执行删除、擦除、同步下载或烧录。

## 二、保留的三款互动体验

| 项目 | 当前规则 |
| --- | --- |
| 空闲 | 无限等待有效互动，释放舵机，不到时间自行表演或叫唤。 |
| 触摸 | 四触点、组合触摸、三击、长按和长按释放；11 类互动各三套变化，每款 33 套，洗牌避免连续重复。 |
| 人体感应 | 稳定无人之后的新靠近可触发无声观察；开机、繁忙、保护和冷却中的旧信号不补表演。 |
| 拿起、摇晃、翻转 | 由 SC7A20H 加速度推断并回应；自身动作结束后重建静止基准，放稳须有新一轮搬动。落体保护独立工作。 |
| 动作幅度与节奏 | 保留三款大行程、160°/s 最终指令限速及连续关键帧衔接；抱持与安静状态使用温和范围。 |
| 头部 | 两款熊猫具有左右转头；恐龙同时有真实颈部抬低头轴，不把熊猫宣传成具有点头轴。 |
| 爬行 | 爬爬熊猫保留有限交替及同步爬行，两轮后回中释放。实际移动距离取决于机构与地面。 |
| 动物声音 | 继续使用外置 Flash 现有录音，按互动匹配并避免连续重复；不合成新叫声，不强行中断旧录音来抢播。 |
| 语音对话 | 三款专用唤醒词和小智听说流程；表达动作按实际播放及内容触发。自由聊天、故事和益智对话依赖云端。 |
| 离线控制 | 原有 12 条固定中文短语；不需要先联网，不冒充离线自由聊天。 |
| 停止与保护 | 明确停止、休息、欠压、芯片过热、落体、看门狗及关机可释放舵机；恢复操作不绕过欠压和过热等保护。 |

关机现在从达到长按条件起，先处理运动收尾，约 1 秒后播放关机提示，再约 700ms 断电。它没有重新启动闲置舵机的“关机表演”。电量严重不足时仍沿用立即切电路线。

## 三、MCP 兼容与诚实反馈

三个产品的 `action`、`body`、`pet_control`、`react_to_user_emotion` 保持原工具名、原参数及默认布尔返回。可选参数 `details` 默认 `false`，原调用方不必修改。无效输入及无动作可执行的分支沿用原有错误字符串或 false 返回。

需要更具体反馈时，例如爬爬熊猫：

```json
{"name":"self.panda.body","arguments":{"action":"look_left","details":true}}
```

返回信息包括：`accepted`、`result`、`reason`、`mode`、`motion_faults`、`motion_busy`、`servo_powered`、`conversation` 和 `physical_completion_verified`。

`accepted=true` 只表示接收或合并了动作请求，不能证明实体动作完成。`physical_completion_verified` 保持 false，因为没有位置反馈。拒绝原因可以是低电量、芯片过热、落体、初始化、停止/休息、维护、看门狗或忙碌/冷却。状态查询工具为 `self.panda.get_pet_status` / `self.dinosaur.get_pet_status`；原 `get_mode` 返回保持。

角色应把这些原因转换成易懂的反馈，例如低电量时说“我需要充会儿电”，繁忙时说“等我做完这个动作”。没有执行时不声称已完成，也不要通过连续重试制造动作风暴。云端角色需在实际平台采用这些规则，本地文档不会自动修改云端配置。

## 四、声音更新的边界

同名更新采用追加数据后替换目录。单个文件下载或校验失败会保留它的旧条目；一次清单中已经成功提交的文件不会因后续文件失败而整批回滚，版本号保留用于下次补齐。

这不是所有介质上都具备掉电原子性的整包事务。NOR 单目录槽、NAND 目录槽用尽后的压实仍有擦写窗口；原驱动已用 CRC 检出异常，但不能宣称任意时刻断电都无损。真实 NOR/NAND 的断电、容量不足和坏块仍需实物故障测试。

空清单不能用于远程清空声音，明确维护删除仍通过相应工具。目录中确有多条合适录音时才有听觉变化；只有一条录音时，固件不会编造更多声音。后台写入期间新的选声可能暂时被拒绝，运动与主循环不等待网络下载；开始互动后的中止还受正在进行的单次读取和短 Flash 操作影响。

HTTPS 验证支持已接入，但现有开发服务地址不会自动变成正式 HTTPS 服务。生产端需要配置真实服务、证书和所有权权限。

## 五、验证与交付

本轮完成 119 项主机测试，涵盖原有唤醒路由、动作库、真实插值输出、限位、回中、保护、24 小时虚拟静置，以及新增模式切换、电源 ADC、关机期限、旧接口兼容和中断下载回归。

新增测试直接执行生产方法及回调，并使用真实 cJSON 解析组件；网络、Flash、时钟、队列和 PWM 为可控替身，未连接真实服务或实物。十二个动作回调分别验证默认布尔与 `details=true` 返回。

三款完整构建使用本机 ESP-IDF v6.0.1；项目首选的 v6.0.2 本机尚未安装。最终本地 `sdkconfig/build` 为爬爬熊猫、“你好小安”，可继续用 VSCode ESP-IDF 插件构建烧录。源码、测试和产物 SHA256、语音模型与合并地址检查保存在[本轮固件](../dist/wzh-product-polish-20261016/README.md)和[验证记录](../dist/wzh-product-polish-20261016/validation.json)。

家庭操作见[家用上手说明](wzh_family_quickstart.md)，逐产品实测见[整机验收表](wzh_product_acceptance.md)。
