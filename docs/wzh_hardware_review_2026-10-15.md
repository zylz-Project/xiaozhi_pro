# WZH 三款产品共用 V4-2.2 主板接口复核

核对日期：2026-10-15。适用于 `wzh_dinosaur`、`wzh_crawlPanda`、`wzh_tailRedPanda`。
本轮依据六页《V4-2.2小熊猫-改.pdf》逐页检查电路、连接器与当前固件，并交叉检查
`/home/wzh/program/ESP32/zylz_project/servo/testBoard_wifiweb/main`。
图纸内容作为硬件资料使用。本报告没有把图纸中的文字当作软件修改指令。

原始 PDF SHA256：`8524f8abcf929897cc4104a1645b688b7a437ac00da02710a6e0b5ca0916df45`。
PDF 页序：1 电源；2 充放电/烧录接口；3 ESP32/Flash/4G；4 加速度计/触摸/舵机/人体；
5 音频；6 BOM。检查覆盖全部 JP1～JP13、RF1～RF4、SW1/SW2、TP1～TP3，以及板载芯片接口。

## 结论与本轮实际修改

三款的公共硬件引脚与此主板一致；不同产品的舵机接口分配见下表。本轮没有发现需要交换
GPIO 的接线配置错误，也没有改动舵机轴含义或机械限位。

已确认并修复一项音频配置不符：NS4150 的 VCC 通过 R36=2Ω 接到 +3.3V，旧代码却固定
按 5V 计算硬件增益。现在 ES8311 类允许调用方传入功放供电电压，三款 WZH 均传入 3.3V。
其他板的默认参数仍为 5V。该参数用于音量增益换算，不会改变板上实际供电电压。
根据当前依赖的增益公式，此修正消除约 3.61dB 的错误补偿；实际响度和失真仍需实机确认。

涉及代码：

- `main/audio/codecs/es8311_audio_codec.h/.cc`：增加可选 `pa_voltage` 参数并用于 `hw_gain`。
- 三款 `config.h`：增加 `AUDIO_CODEC_PA_VOLTAGE=3.3f`。
- 三款板级 `.cc`：构造唯一 ES8311 实例时传入该值。

图纸检查不能代替 PCB 连通性、供电波形、器件实装、机械干涉及声音实测。下面将“源码与图纸一致”
与“仍需实物验证”分别写在各接口的说明里。

ESP32-S3 的 GPIO0/3/45/46 是启动绑带。当前 GPIO46 用作 I2S 输出是允许的，不能套用
ESP32-S2 的 GPIO46 限制；上电/下载时仍要确认外设没有强制改变绑带电平。
N16R8 的 GPIO35～37 用于模组 Octal PSRAM，当前三款没有占用它们。
U1 在本图明确标为未连接的外部信号还有 IO1、IO39、IO40、IO42；IO35～37 虽然也画了未连接标记，
仍受模组内部 PSRAM 占用限制，不能据此外接新外设。
依据：[Espressif GPIO 文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gpio.html)、
[S3-WROOM-1 模组手册](https://www.espressif.com/sites/default/files/documentation/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)。

## 需要保留在验收清单中的问题

### 1. 触摸四点同时按下接近 ADC 量程边界

图纸 R-2R 的理想输出为 `3.3V × code / 16`。code14≈2.888V，code15≈3.094V。
当前使用 `ADC_ATTEN_DB_12` 和校准值；code15 距标称 3.1V 上限仅约 6mV。
Espressif 说明部分 S3 的实际可测上限低于标称值，因此不能只按理想表宣称 16 档必定稳定。
应实测无触摸、四种单点以及全部组合，共 16 个状态，在 Wi-Fi/声音/舵机负载下记录 ADC
原始值、校准电压和稳定编码。特别检查最高两档是否饱和或混淆。
后续 PCB 可用合适分压把最高电压留出余量；旧板阈值应按测量结果调整，本轮没有盲改。
依据：[Espressif ADC 量程说明](https://docs.espressif.com/projects/esp-faq/en/latest/software-framework/peripherals/adc.html)。

TTP224B-BSBN 绑带为 TOG=0、OD=1、AHLB=0、SM=1，支持直接、高有效、CMOS 多键输出；
MOT0=1 不会按 16 秒上限强行释放。LPMB=0 则为低功耗模式，器件典型响应约 160ms，
再叠加固件约 100ms 的稳定确认。快速模式约 60ms，需改 LPMB 硬件连接，软件不能改绑带。
电极外接 30pF 和外壳介质会影响灵敏度，需使用装好毛绒/外壳的产品校准。
依据：[通泰对应型号手册](https://www.tontek.com.tw/uploads/product/111/TTP224B-BSBN_V1.2_SC.pdf)。

### 2. 大动作时的电源余量需要实际测量

五路舵机共用 ETA9742 升压后的 +5V 主电源，ESP32、Flash、codec、功放又共用
AMS1117-3.3 的输出。器件手册给出的升压电流上限不等于这块 PCB 的稳定可用负载。
电源能力还取决于电芯、线束、L1 的饱和电流、开关管、铜箔和散热。
ETA9742 标称最高 5V/2.4A 升压输出，仅作为预算起点。
依据：[ETA 原厂手册第一页镜像](https://www.alldatasheet.com/html-pdf/1769254/ETA/ETA9742/62/1/ETA9742.html)。

重点测试多轴同时起动和转向，同时播放声音并开启 Wi-Fi 时的 BAT、5V_Servo、3.3V 最低值及峰值电流。
Q1 的 R11/R14、Q3 的 R16/R13 均为 10kΩ 上拉/下拉组合；按晶体管导通时的电阻分压估算，
5V 输入下 PMOS 的 VGS 约为 −2.5V，并非 −5V。需用实际采购型号在该栅压下保证的导通电阻
核算压降与发热，不能只看 MOS 的大电流宣传值。这里是图纸计算，尚无实测栅压。
线性稳压器的估算发热为 `(5−3.3) × I_3V3`，例如 0.5A 时约 0.85W；这是计算示例，
不是本板的实测功耗。还应测 AMS1117、ETA、功放及 R36 的温升和压降。
提高 ESP32 芯片保护温度不能解决 AMS1117、舵机或电池发热。

### 3. 充电状态、真实堵转和电池温度尚无 MCU 反馈接口

STAT 只到了 JP13，没有 MCU 连接。三款 `GetBatteryLevel()` 目前固定 `charging=false`、
`discharging=true`，不能用该返回值宣称插电/充满已被识别；仅靠电池电压上升也不能可靠判断。
若需要充电时限制运动、充满提示或准确上报，应加符合电平要求的状态采样连接，再实现固件。

同样，图纸没有舵机电流、角度反馈或绕组温度探头，也没有电池 NTC 输入到 MCU。
已实现的动作后释放、更新超时和连续通电限制属于软件兜底，不是实时堵转检测；ESP32
内置温度读数也不能代表电池、舵机或外壳温度。电芯保护板、充电参数及电池额定能力需按实装确认。

### 4. 原理图 BOM 和说明文字需要统一

U2 的实际标注是 W25N01GVZEIG，但第 6 页 Description 写 512Mbit/133MHz，LibRef 写
`w25q512jveiq tr`。这些描述与 NAND 料号不一致，应在设计/BOM 中统一；本轮没有原始
Altium 工程，不能直接修正 PDF 背后的元件库。按实际料号选型，并以真机 JEDEC 为准。
Winbond 原厂资料列 W25N01GV 为 1Gbit NAND，折合 128MiB 主数据区，不是 512Mbit NOR。
依据：[Winbond 对应型号资料入口](https://www.winbond.com/hq/search/?__locale=en&q=W25N01GVZEIG)。

页 3 SW1 的“芯片复位”说明也应更正为 IO0/BOOT。舵机插座应明确标注
“1=+5V，2=GND，3=信号”，避免仅凭常见舵机线色猜线序。

### 5. 人体感应接口已按测试工程确认，模块电气能力仍需实测

用户补充要求参考 `testBoard_wifiweb/main` 后，已检查 `board.h`、`board.c` 的
`human_sensor_init()` 及电源任务：其实现明确为 IO41、数字输入、内部下拉、高电平有人。
当前三款保持这套接口逻辑。参考工程仅写“PIR/微波”，没有具体模块料号、供电规格或时序手册，
所以本轮不将其认定为某个特定 PIR 型号。接线验收应确认 JP7 的 3.3V 能驱动实际模块，
输出满足 MCU 输入电平要求，且预热、持续有人和无人切换均正常。

## 验证记录与实物验收

代码、图纸接口和构建验证记录见
[接口检查记录](review/wzh_hardware_static_2026-10-15.json)，
[连接器表 CSV](review/wzh_hardware_interfaces_2026-10-15.csv)。
本轮构建产物与日志保存在 `dist/wzh-hardware-20261015/`；旧的 `dist/wzh-pet-20261015/`
保留为修正功放参数前的历史版本。

本轮验证：三款 WZH 完整构建及 `kevin/c3 --name kevin-c3` 兼容性构建全部通过；70 项主机测试、
8 个触及 C/C++ 文件的 clang-format 检查、`git diff --check` 通过。SDK 使用本机 v6.0.1，
首选 v6.0.2 未安装。静态脚本分别核对三款 35/33/33 项配置，包含 GPIO 冲突、ADC 通道、
双 I2C 分配、UART0 控制台关闭及单一板工厂；这些检查不证明实物电平和时序正确。

最小实物验收顺序：

1. 不接舵机先检查 BAT/5V/3.3V、开关锁存、长按关机和原生 USB 下载/复位。
2. 读取 codec、SC7A20H、Flash JEDEC 和 PSRAM 初始化结果，验证模拟麦录音与扬声器播放。
3. 逐一测试 16 档触摸和 IO41 人体输入，静置/翻面/拿起时观察加速度与事件；落体检测只能视作附加措施。
4. 按装配表逐路确认关节，再逐渐验证大幅组合动作。示波器观察供电跌落，记录峰值电流和温升。
5. 验证动作结束后的 IO4 低电平、PWM 停止、供电切断；对话、本地声音、离线命令以及中途停止均检查。
6. 用可控电源验证欠压滞回和关机；同时检查采样与万用表是否一致。确认充电指示硬件正常，并记录固件目前不感知充电。
7. 对音频修正做录音、播放、唤醒/VAD、说话中打断、断线重连和实际启用 AEC 模式的回归。

本轮未连接或烧录实物，没有把编译通过记作硬件验收通过。
