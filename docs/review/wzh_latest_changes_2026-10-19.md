# 最新管理页、手动更新与原生对话复查

日期：2026-10-19。对象：当前工作区新增的 WebConsole、AudioHub 手动模式、管理页及最新 Application 对话改动。此文是检查结果，未修改固件实现或重新打包。

当前版本已使用 StartManual，不再把旧版本的自动注册/心跳问题作为本轮缺陷。三板保留原生小智 Protocol 链路，未引入参考例程的 realtime_ws。上行停止门控、8 包首包缓存、非实时双击提示完成后收音也已经加入。本轮关注这些修正之后仍存在的边界。

## 优先修复

### 1. P1：短回复的 stop 提前清空首包缓存，可能整句无声

位置：`main/application.cc:621`，`Application::OnIncomingJson` 的 TTS stop 分支。

start 通过 Schedule 延后执行，收到的音频先进入 early_audio_；但 stop 在网络回调中立刻 ClearEarlyAudio，再调度状态切换。start、音频、stop 如果都在主任务处理前到达，音频会在 FlushEarlyAudio 之前被删除。

用现有主机框架直接提取当前生产方法回放：

```text
start → 1 个音频包 → 主任务：暂存 1 包，解码入口收到 1 包
start → 1 个音频包 → stop → 主任务：暂存原为 1 包，解码入口收到 0 包
```

建议：start、音频、正常 stop 使用同一会话代次并按接收顺序处理。正常 stop 表示尾部，不应清除同轮尚未送入解码的前缀；用户取消、连接关闭、代次失效才丢弃。补充短句整批到达、连续两轮短句、stop 与双击退出交错的回归测试。不能仅删除一行后就忽略跨轮缓存归属。

### 2. P1：检查后远端清单变化，缓存下标可能下载成另一段声音

位置：`main/boards/common/wzh/wzh_audio_hub.cc:785`，DoUpdate；DownloadFile 使用 `/download/<index>`。

更新使用检查时缓存的 remote_files_、checked_revision_，没有在下载时绑定服务端版本。当前服务端 download 路由通过 path_by_index 查询实时清单。如果检查和下载之间插入/删除文件，下标可能已指向另一段音频；大小碰巧相同时，旧条目的名称与新文件内容可能被一起提交。

提取生产 DoUpdate 回放，更新阶段清单复查次数为 0，仍按缓存 index=0 下载，并使用缓存名称 call 写入。源码及服务端路由均确认下标没有版本约束。

建议：使用稳定文件 ID/名称和清单 revision，下载接口校验预期版本，或者提供不可变的版本下载地址；设备校验文件内容指纹。版本变化返回冲突并要求重新检查，不能在 UI 中把旧选择静默套用到新目录。只在开始时重新读取一次清单仍存在后续下载期间变化的窗口。

### 3. P2：当前播放名称引用了已结束生命周期的栈内存

位置：`main/boards/common/wzh/wzh_web_console.cc:374`。

current 指向 if 块内 AudioFileInfo info.name，块结束后才被 cJSON_AddStringToObject 读取。用该生产代码片段和实际 cJSON，开启 AddressSanitizer 回放，确定报告 stack-use-after-scope。

建议：使用持有内容的 std::string，或者让 AudioFileInfo 的生命周期覆盖 JSON 构造。顺便以播放请求保存的文件身份显示名称，避免目录变动后根据旧下标查到别的文件。

### 4. P2：同名同大小直接判相同，网页不允许更新这类文件

位置：`wzh_audio_hub.cc:747`；`main/assets/wzh_console.html:610`。

DoCheck 只比较字节数，将相同大小标为 same；网页只允许 new/changed 勾选。不同内容但大小相同的录音因此无法通过页面更新。提取生产 DoCheck 回放，只有名称/大小相同而没有内容验证时，结果确定为 same。

建议：有 SHA-256 等内容指纹才显示“相同”。旧接口没有指纹时显示“待校验”，允许主动重下。区分“服务端清单版本”和“本机已更新项目”，部分选中更新不能让整库看起来已经完全同步。

### 5. P2：网页“停止试听”会复位全局解码器，影响小智回复

位置：`wzh_web_console.cc:507`；`wzh_audio_player.cc:39`。

停止接口无条件调用本地播放器 StopPlayback，而 StopPlayback 最后无条件复位所有声音共用的 AudioService 解码器。因此没有本地试听、正在播放云端回复时，点击该按钮也会清空云端回复队列；协议和收音状态却没有相应退出，表现为说话突然断开后又继续。

建议：对当前本地试听任务按所有者/播放代次停止；没有本地任务时返回无操作或忙。校验与取消串行处理，避免刚检查完状态就切入另一来源。保留进入对话、关机等确实需要全局取消的现有专用路径。

### 6. P2：麦克风状态从会话状态推断，提示期间和实时 AEC 下会显示错误

位置：`main/assets/wzh_console.html:427`；状态接口 AddStatus。

页面把 Listening 一律显示为“收音中”，但双击就绪提示期间虽然已经 Listening，实际麦克风处理尚未开启。实时 AEC 模式在 Speaking 中可能继续收音，页面又显示“未开启”。因此页面暂不能用于证明真实收音状态。

建议：设备单独返回收音引擎运行、上行许可、播放实际排空、播放来源、正在取消等字段。页面显示真实状态，同时保留原生会话阶段。不要用软件目标关节角度冒充实际角度。

### 7. P2：HTTP JSON 只接收一次，分段到达会被误判错误

位置：`wzh_web_console.cc:277`，ReadJsonBody。

httpd_req_recv 并不保证一次返回整个 content_len；当前只读一次便解析，TCP 分段时完整有效的更新请求也可能返回 invalid_json。

建议：在 1024 字节上限内循环读满、设置有限超时、验证 JSON 完整结束、拒绝数组外非法项及重复文件名。现有音频包全选请求约 501/715 字节，暂不需要为其盲目扩大请求体上限。

## 页面与产品体验优化

- **更新成功提示相反**：check 与 update 共用 startHubPoll，成功路径固定 toast“检查完成，未写入 Flash”。浏览器模拟更新成功后，任务文案是“更新完成：1 个文件”，toast 却说未写入。应根据任务种类及最终 job_ok 显示结果，不能仅凭 status!=error 判成功。
- **进度不是实际进度**：现在任务运行时固定 55%。后端提供已完成数、总数、当前文件接收/写入字节；数据未提供前使用明确的不定进度动画，不给虚假的百分比。
- **运行中禁用修改选择和再次更新**：renderHub 设置按钮后 renderDiff 又根据 selected.size 重启更新按钮。后台虽拒绝重复任务，前端仍会让用户误以为可以继续提交。
- **客户展示与维护分开**：主界面保留产品、真实状态、音频库与手动更新；curl、接口地址和驱动参数收到展开的维护区。将“Claude 也可直接调用”改成“复制调用参数/导出目录”，是否能控制设备取决于实际连接的工具和网络可达性。
- **补齐动作信息**：音频行显示配套动作是否存在、精编/通用动作、时长与音频指纹是否匹配。新增或替换内容不应继续假定旧文件名对应的精编节奏仍准确。
- **受控访问**：当前热点密码可由 SSID 后缀推得，局域网写接口没有鉴权。面向客户的维护操作应加每设备凭据或 PIN，并限制同源写请求；Hub token 继续留在设备端。
- **维护任务与取消**：更新先占用维护调度、暂停自主展示；增加任务 ID、版本、取消状态与明确忙原因。现有更新不能从网页主动取消，也没有目录容量/追加峰值空间的整批预检。
- **共享层改动范围**：本轮修改了 components/esp-wifi-connect，影响三板之外的 Wi-Fi 用户。仓库规则禁止手改 vendor/component 输出；建议将维护入口尽量收回项目拥有的板级层，确需组件改动时走可重现的组件来源或补丁机制，并验证未设置回调的其他板型。
