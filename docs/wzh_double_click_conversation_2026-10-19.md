# 三款产品双击对话与扬声器衔接（2026-10-19）

最新对话随动、默认归中和密码 1 开发者模式见[本轮更新](wzh_dialog_developer_2026-10-19.md)。以下保留对应阶段的说明，同名固件包以最新固件清单为准。

本次在音画展示方案基础上，统一电源键与BOOT键的双击操作。外部音频Flash沿用用户已同步的新文件，不需要重复写入。

## 操作

| 状态／操作 | 结果 |
|---|---|
| 待机双击电源键或BOOT键 | 暂停本地音效与自主动作，建立会话；就绪提示实际播放完成后开始收音（实时AEC模式仍同时收音） |
| 连接中、收音中或回复中再次双击 | 取消本轮会话，清理排队音频、关闭语音通道，回到本地陪伴 |
| 单击 | 正常运行时不进入对话；BOOT键在启动／配网状态保留配网入口 |
| 长按电源键 | 保留原有长按关机流程 |
| 退出后重新双击或正常唤醒 | 可重新进入新会话，不沿用上一轮的提示音或回复 |

进入对话会从停止／休息模式恢复宠物，只有一段就绪提示，不插入额外Flash叫声。双击退出不把宠物设为持续停止；正常模式回到既有空闲约2秒后的音画展示调度。安静、休息和停止口令仍使用原有控制，退出提示音不会叠加到这些口令或关机流程。

连接尚未开始时收到取消，不再发起握手。取消发生在底层同步握手期间时，立即拒收后续回复；握手返回后关闭通道，不误进入收音或播放进入提示音。底层网络连接的耗时仍取决于网络库与服务器响应。

## 扬声器衔接

- 电源任务只投递双击事件，撤掉原来“先播提示音再切换”的操作。
- 非实时模式下，双击入口先播放一次就绪提示，提示的实际播放队列排空后才发送开始收音并打开麦克风，避免提示音被录入；实时AEC模式以及唤醒词等小智原有入口保持原行为。
- 上行发送在停止后立即丢弃已排队的 Opus 包；TTS start 与首批音频包之间保留最多8包暂存，避免状态切换窗口吞掉首字。
- 电源键采样增加有效性判定：低于1000mV才算按下，高于1200mV才算松开；中间灰区电压和超过250ms的采样中断都视为未知接触，不能累计成长按，也不能凑成双击。
- Audio Hub 后台同步默认关闭（`CONFIG_WZH_AUDIO_SYNC_ENABLE=n`）：开机、联网和日常运行都不主动访问音频服务器。
- 本地音效在进入连接状态时停止，收音初始化的解码器复位完成后才播放进入提示音。
- 双击退出立即阻止旧回复接收；主任务取消待开始收音、清空旧解码／PCM队列，先排好一次退出短提示，再允许待机本地音效进入。
- 本地音效、提示音和TTS共用AudioService。扬声器开启及PCM写入统一放在输出任务，其他播放入口只投递音频。
- 提示音生产者、收到的Opus包和已经解码的PCM都关联播放代次；切换后不把旧生产者的剩余数据重新塞入扬声器。
- TTS开头的解码器清理移到Speaking状态生效前，避免第一批已经接收的语音在后续状态事件里被清掉；重复的TTS开始通知不重复清空当前声音。
- 已排队的旧TTS、转写、情绪和通道关闭任务不能干扰新会话；旧关闭通知在新通道已打开时也不把设备拉回待机或降到省电档。

这些改动处理播放顺序和中断，不修改功放接线、舵机引脚、音效文件或NVS格式。已经送入I2S硬件的极短尾帧不等同于软件排队残留，需要实机确认实际停止延迟。

## 验证

合入[三款灵动动作更新](wzh_lively_motion_2026-10-19.md)后，主机测试157项全部通过（`python3 -m unittest discover -s scripts/tests -v`）；动作修改涉及的C/C++文件通过clang-format检查，`git diff --check`通过。使用本机已安装的ESP-IDF6.0.1构建及打包；本机未安装6.0.2。当前包的大小与分区余量见下表和固件清单。

新增主机回放直接执行生产代码，覆盖三款BOOT回调与状态监听、ADC双击／长按、灰区采样与采样中断恢复、收音／说话／连接阶段的退出、握手前及握手期间取消、取消恰好落在握手检查与进入收音之间、失败后重试、退出后重开、延迟通道关闭、旧TTS／转写／情绪、首包保留、上行发送门控、提示音取消、PCM取消和动作包络清理，以及非实时模式“就绪提示播完再开麦”和实时AEC／唤醒词原路径。通道关闭分别模拟同步及延迟通知；共享音频入口保持WebSocket与MQTT/UDP的调用契约。

软件检查不能替代实机验收。需要装机核对：400ms双击窗口、电源键长按、提示音次数、对话首字及尾音、说话中双击停止、连续进退、弱网连接取消、唤醒/VAD、重连与实际使用的AEC模式。三款分别使用对应固件。
