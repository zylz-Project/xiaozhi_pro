# 小熊猫自然打断：修复播报自行中断（2026-11-03）

本次修复针对 `e32f7d9` 测试版的实机反馈。用户确认没有开口，两次故事播报仍在开始后
触发 `Voice interruption`。原版只通过主机测试和编译，没有通过实机自然打断验收。

## 定位

- 已确认的代码缺陷：本轮参考 RMS 只要超过一次 8，就永久允许打断。参考随后为 0/2
  也不会撤销，VAD 能将残余的自身播报误判为人声。
- 稳定期从进入 speaking 计时，网络等待和播放预缓冲也占用这 240 ms，实际出声时可能
  已无稳定期。
- 新补充日志中离线音效的参考 RMS 出现 829、1718、4282，证明通路曾收到播放参考。
  每两秒一次的瞬时采样不能证明整段 TTS 都没有参考，也不能证明 AEC 效果合格。
- 麦克风 RMS 曾达到 19000 左右，存在削顶风险；RMS 日志本身不足以确认削顶。
  新版在重采样前直接统计 ADC 满幅采样，避免滤波后遗漏。

ES8311 的数字回送是串口输入数据的路由，不能等同于扬声器输出已经完成消回声。
依据为 [Everest ES8311 User Guide，第 25 页数字反馈](https://files.waveshare.com/wiki/common/ES8311.user.Guide.pdf)
和本地 `esp_codec_dev` 驱动中的 ADCL + DACR 配置。

## 修复

1. 删除“本轮曾见过参考”的锁存条件。参考能量门槛改为 32，最近一次有效参考及最近一次
   采集均须在 120 ms 内。短音素空隙允许通过，长空隙、停滞或异常输入重启校准。
2. 真正采到播放参考后，收集 600 ms 的 post-AEC 残余回声基线，再要求连续 180 ms
   同时满足 VAD 与 `max(260, 3×噪声 RMS, 2.5×校准残余 RMS)`。
   这是保守的测试初值；校准期内不接受自然打断，短回复可能在完成校准前结束。
3. 输入一帧中超过 1% 采样达到绝对值 32700 时，暂停自然打断至少 240 ms，随后重新校准。
   参考为零且非静音时拒绝自然打断；静音仍要求采集正常更新。
4. 缺失参考、削顶和恢复会撤销旧确认 token。主任务在清空播放之前，先在捕获锁内接受确认
   并提交前缀；失败不产生半次取消。已接受的确认不再因有意停止扬声器而失效。
5. 仅参考模式采用 24 dB 输入增益，原普通路径保持 36 dB。测试版采用
   `AFE_MODE_HIGH_PERF` / `AEC_MODE_FD_HIGH_PERF` / `AEC_NLP_LEVEL_VERYAGGR`。
   是否影响远场收音和处理余量须以实机为准。
6. codec 每次 open/resume 后重写并读回 `0x44=0x58`，记录 SDP 格式和输入增益；
   不修改厂商组件，不新增 I2S 驱动，不改板卡引脚。
7. MR 日志增加两秒窗口内麦克风/参考峰值、有效参考帧数、削顶帧数、参考可用状态、
   post-AEC 残余 RMS 与门槛，避免只凭一个瞬时的零值判断通路。

720 ms 有界 Opus 前缀、捕获/回复代次、普通唤醒词打断、双击进出以及两种传输的 auto
协议继续使用原实现。服务器仍需先发新的非空 STT，再发新 TTS；见
[原测试版的协议约束](wzh_tailredpanda_voice_barge_in_2026-11-02.md)。

- 全量主机测试 **218 项通过**，73.267 秒；人声打断相关 14 项通过 ASan/UBSan（含泄漏检查）。
- 普通小熊猫、C3/4G 和最终小熊猫打断测试版均使用 ESP-IDF 6.0.1 完成规范构建；
  本机没有首选的 6.0.2。普通镜像没有启用自然打断。
- 触及的 C/C++ 通过 clang-format 检查，`git diff --check` 通过。
- 日志：`/tmp/wzh-tail-barge-in-20261103/`。新增回归覆盖延迟播放、残余回声、单次参考尖峰后
  持续为 0/2、输入停滞及恢复、削顶、静音输入活性、恢复后旧确认不能复活，以及接受失败不清空播报。

`MR capture` 的 `ref_ready` 用于本轮打断监测；不在监测期间时，它不能作为通路故障判断。
先查看 `ref` 峰值与 `active` 帧数，再结合播报时的残余、门槛和削顶计数判断。

实机先以原使用音量、安静环境连续讲故事，确认无人说话时不再自行打断；随后在开始出声
一秒后正常说新问题，检查停旧回复、首字保留和新回复，再测试音量、距离、舵机、背景声、
唤醒词、双击退出与断网重连。参考持续缺失或 ADC 削顶时，新版会拒绝自然打断，保留原有
唤醒词/按钮路径；这不代表自然打断已经验收通过。
