# 爬爬熊猫：阿里百炼音色复刻

在设备管理页进入开发者模式后，选择“音色复刻”标签，在“阿里服务设置”中配置 Key，并在音色列表选择需要的音色。固件默认使用阿里服务，配置在下一轮小智回答生效；正在合成的回答使用开始时保存的配置快照，页面不回显 Key。升级后直接沿用设备原有阿里配置。

阿里选项使用北京地域的 `qwen-audio-3.1-tts-flash`、音色 ID 以及 DashScope API Key。首次使用时，保存阿里 Key 后选择一个系统音色，或通过下述网页、语音流程创建新音色。音色列表上的删除操作会删除阿里云中的对应音色。音色 ID 与阿里账号及创建时目标模型绑定。Key 或 ID 未配置完整时继续使用小智官方原声。

ESP32 直接请求 `https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer`，设置 `X-DashScope-SSE: enable`，请求 24 kHz、单声道 PCM。设备分段解析 SSE 事件中的 Base64 音频，解码后送入原有有界 PCM 队列和唯一扬声器任务，边接收边播放。每个请求仍只提交一整句文本，并非双向流式输入。非流式兼容路径仍保留，下载时仅接受北京地域 `dashscope-result-bj.oss-cn-beijing.aliyuncs.com` 的结果地址，不向下载地址发送 API Key。

阿里音频经独立的 192000 字节 PSRAM 环形缓冲（约 4 秒）进入现有扬声器任务；请求线程不必等扬声器播完当前句就能准备后一句。开始时优先积累 500 ms，等待不超过 1.2 秒；播放中缓冲耗尽后，按耗尽次数逐步提高恢复播放的缓冲目标，最多 300 ms、等待最多 350 ms，以减少反复短断音，代价是恢复时可能稍有等待。缓冲满时网络线程等待，避免无限占用内存。`Ali PCM buffer underruns` 记录缓冲曾耗尽后再次收到数据的次数，`starvation_ms` 记录这些等待的累计时长；其中也可能包含等待小智发送下一句的正常间隔，不等同于实际听到的断音。句子尚未从小智到达、网络或合成速度长期慢于播放时，仍可能出现停顿。实机需验证首音延迟、连续故事、打断和网络波动。

小智通过 `sentence_start` 下发的 `% search_music...`、`% self.panda.react_to_user_emotion...` 等纯工具状态不进入克隆音色合成；带正常文本的消息不会按此规则过滤。遇到已观察到的 `% play_music...` 状态时，熊猫取消当前克隆播放并切回小智原始音频，以播放服务器提供的音乐。遇到已观察到的“好嘞，给你放了…”或明确的歌曲播放结束提示，会重新启动克隆音色合成结束语。小智协议目前没有已知的可靠歌曲结束事件：其他结束语可能继续使用原音，文本匹配也存在误判可能。服务端提示和 UDP 音频可能乱序，切换处可能截断音频，需真机验证。

阿里请求使用自然语言 `instruction`，让模型根据文本语义和标点调整语气、语速、情绪；实际表现取决于模型和所选音色。只合并请求开始时已经在队列里的短文本，不等待未来句子，批次不超过 240 字节；这减少积压时的请求次数，但无法消除官方文本下发和阿里合成首包的固有等待。

### 直接说话打断实验

实机测试发现该实验会被播放声音和环境声误触发，当前爬爬熊猫构建已关闭，不应视为已实现可靠的直接说话打断。手动启用 `CONFIG_WZH_PANDA_SOFTWARE_AEC` 时，从经过扬声器保护处理的数字 PCM 构建一个 24 kHz 软件参考通道，和单路 ES8311 麦克风采样交错送入 AFE；参考缓冲上限 200 ms，初始对齐 40 ms 是未经实机校准的估计。对话切换到设备端 AEC 实时模式，播放中须先检测到安静，然后连续检测至少 700 ms 人声，主循环每秒检查一次并中断当前声音、进入收音。`Direct VAD: speech/silence` 和 `Direct speech interrupt` 可用于观察，日志不含音频原文。

实验必须验证安静房间播放、音乐/人声播放而用户不说话、不同距离和音量下说话、唤醒词、连续对话、打断和重连、离线音效、内存低水位和长时间运行。软件参考时延、扬声器与麦克风的实际声学路径和 AEC 效果均未校准，可能误打断、漏检、改变首音或识别表现。不要据此宣称完整回声消除或免唤醒打断已达产品要求。要回退，在 `main/boards/wzh_crawlPanda/config.json` 的 `sdkconfig_append` 中将实验项改为 `CONFIG_WZH_PANDA_SOFTWARE_AEC=n`，并加入 `CONFIG_USE_DEVICE_AEC=n`，然后按项目脚本重新构建并烧录。不要直接编辑生成的 `sdkconfig`。

Key 经现有设备管理页输入。管理页是 HTTP，NVS 未加密；仅在可信设备热点和周围环境下使用测试 Key。设备会把小智回复文本发给所选语音服务，请勿在日志、源码或聊天中粘贴 Key。句子按序处理，等待队列最多 64 句且总文本不超过 16 KiB；达到上限后拒绝新句，但保留并播完已接受的句子，记录警告且下一轮回退官方音色。被打断的旧网络请求尚在退出时，最多保留一轮新的克隆请求及其有界文本队列，待旧任务释放后自动启动；旧请求超时会增加新回复延迟。音色配置不足、内存不足或合成失败等其他情况仍可能回退官方音色。任意长度的故事仍不能保证完整，实际延迟、内存、打断需要实机测量。

流式响应的单个 SSE 事件限制为 96 KiB，单句累计 PCM 限制为 4 MiB。流中断、格式不符或超限时会停止当前请求；已经播放的片段不会自动重放，剩余语句可能中断。不要根据主机模拟结果假设真实服务必定满足这些限制。

VS Code 选择 ESP-IDF 6.0.2，运行 `WZH: 编译爬爬熊猫 (ESP-IDF 6.0.2)`，然后选择正确串口及 UART 烧录。打开管理页→开发者模式→音色复刻，在阿里服务设置中配置 Key，再从列表选择音色。Monitor 中 `Starting voice cloning provider=ali`、`Requesting speech provider=ali` 表示调用路径；`Ali first PCM received` 表示首段数据到达，`Speech audio queued for playback` 表示该次请求数据已排入播放队列，均不等于扬声器或音质已通过实机验收。不要通过擦除整个 Flash 来切换服务。

## 语音发起阿里音色复刻（实验，待真机验收）

爬爬熊猫选择阿里语音并配置阿里 API Key 和一个可用的当前音色后，在在线对话中说“复刻音色”。设备用当前音色提示“那请你从一数到二十吧”，播放结束后采集 16 kHz 单声道音频；录音最多 20 秒，检测到累计至少 5 秒人声且停顿约 1.5 秒后结束。建议在安静环境、靠近麦克风以自然语速数数，不必唱歌。录制期间的语音不再发往小智会话。录音只在 PSRAM 中暂存，通过 HTTPS 直接发送阿里百炼，固件不会把录音保存在 Flash。

设备以 `qwen-audio-3.1-tts-flash` 创建音色并查询状态，状态变成 `OK` 后替换 NVS 中的阿里音色 ID，之后使用新音色说“我完成复刻啦”。失败时保留原先配置，可再次说指令重试；网络超时可能导致云端已创建但设备未得到结果，本地不会自动重发创建请求。每次成功创建会在阿里账户留下音色，未自动删除旧音色；账户配额和计费以阿里官方说明为准。双击电源键退出对话可取消进行中的操作，网络请求正在阻塞时退出可能有所延迟。设备和服务可用性、录音质量、声音相似度与阿里账户权限需要实际测试。

该功能尚未解决的“你好小安”播放中打断和歌曲结束后音色问题见 `docs/wzh_voice_open_issues.md`。

录制期间，爬爬熊猫暂停本地唤醒词和触碰、姿态驱动的动作，由动作任务释放舵机；安全保护和电源键仍生效。录音结束有短提示音，管理页开发者模式显示当前阶段和失败类别。复刻或手动切换阿里音色时，设备保留上一个 ID；可在开发者模式“切回上一个音色”，也可在设备空闲时点击“试听当前音色”。新旧 ID 保存在单条 NVS 记录中，旧版 `ali_voice` 配置在首次更新时自动迁移；这不删除阿里云账户中的任何音色。

串口 `Reference upload complete`、`Create response` 和 `Voice ready` 分别记录建连与上传、服务响应和状态查询耗时，不输出密钥或录音。上传采用受限缓冲分块发送，PSRAM 不足时回退较小分块。复刻会暂时保持扬声器输出设备开启，以减少等待后关闭再重开 I2S 的次数，代价是这段时间的功耗可能增加；录音麦克风仍按独立逻辑关闭。以上表现需要真机验证，包括动作停止、功耗、提示音、试听和异常断电恢复。

## 音色管理与网页录音

在熊猫原有管理页进入开发者模式，打开“音色复刻”标签后，使用“音色管理”刷新阿里音色列表。系统音色为当前 `qwen-audio-3.1-tts-flash` 北京地域内置音色，不占专属音色名额。专属音色最多 10 个；选择“使用”会在下一轮在线回复生效，可重命名或删除不再使用的专属音色。正在使用的音色须先切换才能删除。删除请求会删除阿里云对应音色，不只删除本地名称；删除上一个音色时，本地回退记录一并清除。

设备通过 Wi-Fi STA 的完整 48 位 MAC 转成固定 10 位字母数字前缀，再按此前缀查询、创建和删除云端音色。此隔离防止管理操作误把其他前缀的音色列入当前设备，但并不构成不同设备之间的安全边界：使用同一个 API Key 的人仍拥有该账号权限。旧版通过公共 `panda` 前缀创建的音色不能可靠判定归属，不会自动导入或删除；此前设置的当前音色仍可正常使用。更换设备主板或恢复/擦除本地 NVS 可能改变可见的显示名称；阿里音色 ID 和云端音色不因清除本地名称而自动删除。

中文名称存储在本机 NVS，阿里云音色 ID 本身不可通过本功能改名。本机查询云端数量后才允许创建；若云端创建请求已发送但结果因断网、超时或掉电无法确认，设备记录未确认的创建操作，暂停继续创建，直到刷新列表发现新增音色。此机制优先防止重复创建；若云端最终没有创建音色，自动恢复可能无法完成，需结合阿里账户核查，不能简单反复重试。已有云端账号可能有账号级总配额和费用，具体以阿里官方规则为准。

网页可以输入名称后点击“用熊猫麦克风录音”，设备空闲时会提示从一数到二十，并直接采集熊猫麦克风；也可以使用浏览器录音或选择音频文件。浏览器录音或文件由页面转换为 16 kHz 单声道 PCM，上传到熊猫后由设备直接请求阿里，录音只暂存在运行内存中。音频长度为 5～20 秒。浏览器要求用户授权麦克风，且绝大多数浏览器只允许 HTTPS 或 localhost 页面使用 `getUserMedia`；原来的 `http://192.168...:8080/` 页面在部分浏览器中不能直接网页录音。此时可使用页面的“选择或录制音频文件”，由支持的手机浏览器调起系统录音，或者先用手机/电脑录音再选择文件；具体支持随浏览器而异。文件不离开页面，直到用户点击上传创建。

在线对话时说“切换音色”，熊猫依次播报本地记录的专属名称及系统音色；随后在 60 秒内说出目标名称，即可保存切换。说“取消”保留当前音色。每步本地选择会关闭旧对话通道并重新连接，等待用户下一句之前丢弃迟到的服务器语音；服务器仍可能保存跨会话上下文，不能保证其遗忘此前的识别文字。自定义名称应尽量简短、读音明显不同，避免语音识别混淆。该流程、云端服务、浏览器麦克风权限、设备内存和播放效果仍须以实际设备验收为准。
