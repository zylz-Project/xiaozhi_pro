# 小熊猫大幅动作、左右均衡与高翘尾修正

用户实机反馈上一版头部不明显、摆尾小且偏左、上翘不足。本轮以实际输出路径为验收对象，保留大幅动作，通过连续曲线与足够的时长控制换向。没有放宽机械限位：头部仍 30°～150°，尾左右仍 6°～174°，尾上下仍 10°～178°；**尾上下角度越小，翘得越高**。

## 上一版的问题

- 长声音的头部目标额外乘了 0.72；配套还有表达窗、入场、结束混合，短录音没有足够时间完整看到两侧。
- 普通录音把连续摆尾抽成稀疏关键点，并随机保持部分点，可能漏过左右极值；允许的机械范围很大，不等于实际执行到了。
- 配套记录本身的单侧偏置与多层混合叠加，使部分表现左右不均。只随机镜像不能保证每一段都完整摆向两侧。

参考了用户指定的 `final/newWebServer_Project/tailRedPanda/main/auto_run.cc`，重点核对 `kIdleHighWag`、`kCuriousTailLift`、`kPlayHighSweep`、`kPlayEight`、`kCuriousTrack` 和镜像平衡。参考例程高翘帧有 24°／26°／28°，头部和尾左右都有清楚的大幅往返；本轮恢复这些表现特点，继续使用小智原有音频和对话。

## 当前执行方式

普通 Flash 动物音与手调配套均通过新的连续时间轨迹执行，直接按实际播放时钟采样，避免抽点丢失极值或随机保持吞掉另一侧。八类尾巴轨迹保留高翘宽摆、波浪、上下起伏、八字、高位绕弧等差异；每文件仍有 32 种随机变化。

- 正常头部目标每侧 56°～59°，移除额外缩幅，并完整走过两侧；不会因尾巴为主而关闭头部。
- 正常尾左右每侧 82°～84°，每段都完整经过左右两侧；相邻表演轮换先摆哪一侧，明确单关节方向口令不受随机镜像影响。
- 高翘轨迹真正到现有限位的 10°附近；高尾类别会在高位持续摆动，而非一到高位就被缩幅拉回。
- 不用减小幅度来适应短音频：从真实姿态平滑入场后，至少给 2550ms 完成两侧；很短的声音允许动作继续，完整展示后再回坐姿。取食保持可见头部和大幅摆尾；睡眠仍保留安静表达。
- 单独收势采用五次曲线，正常峰值上限 130°/s、睡眠 65°/s；整体仍受 400°/s 最终指令上限约束。退出、停止仍由现有控制从真实输出姿态接管，保护仍直接释放。

手调配套录音、选择优先级与原始数据保留。为了纠正偏置和范围不足，**新大幅轨迹成为小熊猫配套动作的主体**，原记录以自身范围中点去偏后保留最多约 3°的细节，避免原本单侧记录继续拉偏整个动作。大熊猫、恐龙继续使用原有动作路径。

## 输出回放结果

主机执行生产 `SoundChoreography` 和小熊猫实际 `OutputPose()`，按 20ms 采样模拟最终 PWM 角度。以下只比较 14 套手调配套中的常规动作，共 384 种变化，睡眠单独验证。**这是软件命令回放，不是实机测量。**

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 头部平均总摆幅 | 64.1° | 113.0° |
| 尾左右平均总摆幅 | 104.0° | 165.5° |
| 平均最高翘尾角度（越小越高） | 32.7° | 10.6° |
| 最差左右摆幅差 | 49.0° | 2.3° |
| 最差全段平均侧偏 | 19.3° | 0.83° |

新回归同时覆盖 14 套配套、18 个普通动物音，每种 32 个变化，共 1024 段。常规动作逐段要求：头部两侧均至少 46°、尾巴两侧均至少 78°、最高翘尾不高于 24°、高位时间不少于 200ms、左右范围差不超过 8°，并检查两侧停留时间和平均侧偏。从不同中断姿态开始，也检查连续入场、400°/s 限制、有限平滑收势和最后释放。

完整数据见[最终输出对比](wzh_tail_balance_comparison_2026-10-21.json)。其中旧版短 Flash 的记录仅反映旧通用播放器，因为旧运行分支还可能选择完整动作库；上表使用真实旧配套路径，避免混用。三款全部配套的[目标轨迹对比](wzh_tail_balance_product_comparison_2026-10-21.json)确认大熊猫、恐龙本轮数值不变。

## 编译与验证

最终全量测试、三款编译及包体校验完成后更新。本轮未烧录；仍需实机确认高翘时的机构空间、实际牵引／负载、左右安装中位和连续运动供电。若真实机构的左右中位不等于软件 90°，需要按设备测量处理，不能靠随机偏向抵消。
