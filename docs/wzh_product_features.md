# WZH AI 陪伴型玩具宠物：完整功能介绍

更新日期：2026-10-16
适用产品：爬爬熊猫、恐龙、摇尾小熊猫  
版本依据：当前分产品 WakeNet 固件，已加入触摸/拿起体验修正、已有外置 Flash 互动选声、三款大幅快动作、头部补强与参考工程连续有限爬行、三套互动变化、扩展性格动作、连续动作与自身震动过滤、SC7A20H 重试诊断，以及静置误触发、整机模式切换、关机和声音维护体验优化。

## 1. 产品定位

这三款产品通过声音、身体动作和感应交互提供宠物式陪伴，面向儿童及青少年。
联网时可以进行语音聊天，并用肢体动作配合回答；没有网络时，仍可通过触摸、人体感应、
拿起或摇晃等动作，以及固定的中文语音口令与宠物互动。

故事、知识问答、猜谜和益智对话由接入的云端模型与角色配置承载。
当前固件提供语音和动作交互入口，尚未内置独立的故事课程库、益智游戏关卡或学习进度系统。

| 产品 | 可活动部位 | 表现特点 |
| --- | --- | --- |
| 爬爬熊猫 | 头部、左右前肢，共 3 路舵机 | 转头观察、前爪挥动、吃竹、拥抱、扒动与爬行编舞 |
| 恐龙 | 头左右、颈左右、颈上下、尾左右、尾上下，共 5 路舵机 | 伸颈观察、仰头吼叫、低头进食、多轴摆动和摆尾 |
| 摇尾小熊猫 | 头部、尾巴左右、尾巴上下，共 3 路舵机 | 转头、摇尾、尾巴画弧、撒娇和开心展示 |

爬行距离、牵引力及动作效果受舵机、机构、装配和地面条件影响，目前没有位移反馈或自主导航功能。

## 3. 开机、配网与基本操作

### 3.1 开机过程

设备启动后初始化音频、外部声音存储、舵机控制、电池采样与感应模块，再进入网络连接流程。
初期先禁止舵机，等待电池分压电路稳定；约 15 秒后开始确认有效电压，连续取得 3 次有效采样后
才允许动作。因此，刚开机没有立刻动作不一定是异常。

已有有效语音资源且没有待执行资源下载时，本地语音模型会提前加载；没有完成配网或正在等待
云端激活时，也可使用已就绪的本地命令。模型缺失、损坏或等待更新时，离线识别可能暂不可用。

### 3.2 Wi-Fi 配网

没有已保存的 Wi-Fi 时，设备开启对应产品的配网热点：

| 产品 | 热点名称前缀 |
| --- | --- |
| 爬爬熊猫 | `CrawlPanda-XXXX` |
| 恐龙 | `Dino-XXXX` |
| 摇尾小熊猫 | `RedPanda-XXXX` |

手机连接热点后，通过配网页扫描并选择 Wi-Fi、填写密码；常用访问地址为 `192.168.4.1`。
配网页默认中文，可切换语言，并保留 OTA 服务地址配置。网络凭据由设备保存，后续启动自动尝试连接。
路由器中显示的设备主机名也使用对应产品前缀。

配网页用于连接网络；当前没有独立的产品 Web 控制台，也没有手机家长管理 App。

### 3.3 按键操作

| 操作 | 功能 |
| --- | --- |
| 模拟电源键双击 | 开启或结束对话 |
| 模拟电源键长按约 1.5 秒 | 发起正常关机，停止本地声音并请求回到默认姿态，再断开供电 |
| GPIO0 按键单击 | 正常时切换对话；启动/配网阶段进入配网流程 |
| GPIO0 按键双击 | 正常或安静时进入停止；停止或休息时恢复活动 |
| EN 复位键 | ESP32 硬件复位，用于调试维护 |

电源键在开机时被按住，需要先释放一次才接受后续关机操作，避免把开机按压误判成长按关机。
电源 ADC 异常会取消按压和双击，恢复后先确认松开。正常关机先结束互动，仅让正在通电且健康的舵机在约 900ms 内有限回中，再播放关机提示并断电；已释放或受保护时不重新启动舵机。严重欠压仍立即切电。

### 3.4 通过唤醒词开启对话

| 产品 | 唤醒词 | 专用模型 |
| --- | --- | --- |
| 恐龙 | **小龙小龙** | WakeNet9 |
| 爬爬熊猫 | **你好小安** | WakeNet9 |
| 摇尾小熊猫 | **你好星宝** | WakeNet9l |

和原版小智一样，先说本款的唤醒词，网络与云端激活就绪后，听到提示音再说问题，例如
“讲个故事”。唤醒不会先提交额外的动物叫声或探索表演。对话中的继续聆听、结束及重新唤醒沿用现有小智流程；说话时再唤醒可触发打断。
离线也可检测唤醒词并恢复宠物活动，开放式聊天仍需要网络；配网/激活期间不会强行建立聊天。
触摸、姿态和人体感应继续触发本地宠物回应；“醒醒”只恢复宠物活动。

WakeNet 处理专用唤醒词；MultiNet7 同时保留下面 12 条本地短语，两者复用同一麦克风和 AFE。
“你好小智”不再作为这三款新固件的默认唤醒词。更新时必须同时更新 app 和 assets。

## 4. 离线模式：不用网络也能互动

产品中的“离线陪伴”指没有进行在线对话时的本地宠物行为。即使 Wi-Fi 已连接，
只要当前没有正在建立会话、听用户说话或播放在线回答，也可以进行本地互动。

### 4.1 触摸互动

四路触摸电极可独立触发，也可以组合触摸：

| 触摸方式 | 回应 |
| --- | --- |
| 单点轻触 | 按触点区分的回应，每个触点有三套独立洗牌动作；爬爬熊猫 SW1=头部、SW2=左前肢、SW3=右前肢、SW4=双前肢 |
| 同时触摸两点及以上 | 玩耍短回应 |
| 同一触点相邻轻触间隔不超过约 1.4 秒，连续三次 | 更活泼的回应，触发后重新计数 |
| 保持触摸约 1.2 秒 | 进入温和回应，降低动作幅度 |
| 持续保持长按 | 延长温和状态，不反复重新启动同一动作 |
| 长按后释放 | 给一次轻柔的观察回应 |

正常本地模式下，回应从外置 Flash 现有动物声音中按输入匹配，有其他条目时避免连续重复；在线对话中不叠加本地叫声。
安静模式下可以有较小幅度的无声触摸回应。停止和休息状态需要明确唤醒，普通触摸不会自动解除。

四个触点安装在身体哪个位置由装配决定，当前固件没有把它们固定解释为“头、背、肚子、尾巴”。
触摸芯片采用低功耗模式，并叠加软件稳定判定；启动或异常恢复时须先确认全部释放，再接受新触摸。ADC 失败会取消旧接触，不补长按或释放动作。最高电压档和穿过毛绒/外壳后的灵敏度仍需实测。

### 4.2 人体感应

人体感应通过 IO41 数字输入工作，内部下拉，高电平有效，与测试工程一致。
上电前约 10 秒抑制招呼；之后先有约 3 秒稳定无人信号，再有约 200ms 稳定的新高电平，才可能回应。
新靠近时动作必须已允许、舵机未通电，且距上次招呼至少约 60 秒。启动、繁忙、保护或冷却期间的旧信号不会等到以后补表演。

招呼采用无声观察动作，持续高电平不会重复招呼。安静、停止和休息时不主动招呼。
详细边界见[静置误触发修正](wzh_quiet_idle_2026-10-16.md)。

### 4.3 拿起、摇晃与翻面

SC7A20H 提供三轴加速度，固件据此估计拿起、晃动、翻面和大角度倾斜，采用较温和的动作回应。
舵机通电及释放后约 600ms 暂缓姿态陪伴触发，落体保护仍独立运行；之后用约 300ms 连续静止样本重建基准。
启动、断连恢复及保护恢复也会重新确认基准，不以校准触发回应。

明显姿态事件成功接收后约 900ms 内不重复，拒绝的短事件可有限重试。
上轮互动结束后必须先有静止分隔，再有新的搬动并随后稳定，才可推断放稳并轻柔回应；仅仅等待不会触发。
这些是加速度启发式估计，不能准确区分“放到桌面”和“被人静止抱着”，也不能检测是否被拥抱。
加速度计支持启动失败或读失败后的重新探测；缺失不会阻塞对话与其他交互。

### 4.4 离线语音口令

默认启用中文 MultiNet7 固定关键词识别。以下 12 条短语在本地处理：

| 口令 | 功能 |
| --- | --- |
| 开心 | 提交开心动作 |
| 撒娇 | 提交亲昵动作 |
| 吃东西 | 提交进食动作 |
| 摇摇头 | 提交摇头动作 |
| 向左看 | 提交向左看动作 |
| 向右看 | 提交向右看动作 |
| 停下 | 停止声音和动作并释放舵机 |
| 别动 | 与“停下”相同 |
| 安静 | 暂停自主表演和本地叫声 |
| 睡觉 | 进入持续休息 |
| 晚安 | 与“睡觉”相同 |
| 醒醒 | 恢复正常陪伴，并提交探索回应 |

本款专用唤醒词可恢复宠物活动；联网服务就绪时继续发起在线会话。12 条本地短语无需先说唤醒词。播放 Flash 声音或在线播报及约 350ms 尾声期间，会启动动作的本地口令被忽略以减少自身回声误识别；停止、安静和休息类仍可处理，正常 WakeNet 唤醒流程保留。
“抬头、挥手、摆尾”等更丰富的身体指令属于联网语义或 MCP 工具能力，尚未全部加入离线词表。

语音命令都受当前保护状态约束。“醒醒”不能绕过低电压、芯片过热、落体、升级或关机锁。
离线识别提供固定口令控制；自由聊天、故事生成和开放知识问答需要联网。

### 4.5 互动后的回应与本地声音

默认安静等待，不定时开启随机动作、动物叫声、环境音或待机生命脉冲。
此前“一小时不自行表演”是一小时的主机模拟覆盖，并非待机周期；一小时后仍继续等待，不会到点开启表演。
触摸、姿态、人体、语音或明确工具请求提供有效事件后，宠物执行相应回应；结束后释放舵机。
开机和结束对话也不会自动提交探索表演。对话退出或断网会消耗旧表达请求，重连不恢复旧编舞。开关机、配网等系统提示音保留。

普通宠物回应叫声启动间隔至少 12 秒，播放请求成功后才记录；冷却中动作仍可回应。
明确触摸与姿态互动单独使用约 650ms 的声音启动间隔，温和窗口仍可发声；已有录音自然播完，新触摸只替换动作，扬声器忙时不叠加或累积新声；安静模式保持无声。
三款具体动作变化见[互动体验改进](wzh_product_experience_2026-10-16.md)，最新动作衔接、震动过滤和日志规则见[流畅度修正](wzh_fluent_motion_2026-10-16.md)。
人体招呼仍采用无声观察。
长录音继续播放时，不再仅因录音未结束而维持离线摆动；在线 TTS 和显式声音表演各按自己的规则工作。

互动与普通表演声音都来自外置 Flash 的已有音频，不使用合成替代音。目录为空时保持无声动作。
优先匹配亲近、开心、好奇或受惊文件，有多个动物声音时跳过上一条；具体变化取决于实际音频库。
单次声音按完整原文件解码，长度取决于素材，也可由停止、休息、安静、维护或进入对话取消；没有录制、剪裁或重新写入声音素材。
长时间没有互动会持续等待，不再使用“前十分钟定时表演、之后暂停”的旧策略，也不自动关闭整机。
维护禁动保留，升级、硬件启动、录音测试及致命错误阶段禁止运动。

## 5. 在线模式：对话、情绪与身体表达

### 5.1 语音聊天、故事和益智对话

麦克风收音后，通过小智协议接入配置好的语音/模型服务，再从扬声器播放回答。
可以通过云端角色承载日常聊天、故事讲述、猜谜、知识问答和鼓励式陪伴。
具体内容、可记住的上下文、可调用的知识工具与年龄适配策略，由服务端配置决定。

固件支持 WebSocket 与 MQTT/UDP 两种协议路径，实际使用哪一种由接入服务配置决定。
网络中断时结束在线语音通道，回到当前模式允许的本地陪伴；停止或休息状态不会因断网而自行恢复。

### 5.2 根据用户表达做动作

动作可以由云端情绪事件、模型调用动作工具，以及用户转写文本的轻量规则触发。
例如“好开心”可触发开心展示，“喜欢你”可触发亲昵，“不开心、难过、担心”采用温和倾听。

文字处理先识别停止、休息和否定，再检查明确身体指令，最后进行情绪规则匹配。
例如“别摇头”优先停止，“不开心”不会因包含“开心”而触发庆祝。
这些规则用于基本兜底，复杂语义、反讽和引述仍依赖云端理解；设备端没有独立的声学情绪识别模型。

### 5.3 根据宠物自己的回答配合动作

宠物回答中的开心、亲昵、安抚、思考、进食等内容，也可以触发对应身体表达。
表达会等待扬声器实际出现声音后再提交；无声或已经过期的表达会丢弃。

声音播放期间，控制器使用真实输出 PCM 的响度包络驱动头、前肢、颈或尾巴的平滑变化。
在线 TTS、本地声音和系统提示音共用这一输出链路。同步粒度为句子事件与声音响度，
尚未实现逐字、逐音素动作时间轴。

### 5.4 对话中断与动作优先级

进入在线对话会停止本地声音，避免与云端回答争用扬声器。
停止、安静、休息控制会中断当前对话和排队声音。
普通动作指令主要控制动作，不会一律关闭会话。

明确指令优先于普通情绪和感应回应；同类请求会合并，待执行的过期请求会丢弃。
控制器只保留最新待处理意图，避免长时间排队后才执行旧动作。
与当前说话绑定的动作会在语音结束或打断后取消，后续运动继续受速度和行程限制。

说话时唤醒、回声消除和语音打断的实际效果与 AEC 配置、单麦克风安装及机械噪声有关，需实机联调。

## 6. 动作体系与三款差异

### 6.1 共同的八类表演

| 动作标识 | 表现用途 |
| --- | --- |
| `discover` | 观察、探索、好奇 |
| `affection` | 亲昵、撒娇、靠近感 |
| `happy` | 开心、玩耍、庆祝 |
| `proud` | 展示、精神昂扬 |
| `eat` | 吃竹、啄食、寻找食物等模拟动作 |
| `listen` | 侧耳、关注、温和倾听 |
| `startled` | 惊讶、警觉、后缩 |
| `sleepy` | 困倦姿态或短表演 |

`sleepy` 动作是一段编舞；语音“睡觉/晚安”和 `rest` 控制会进入持续休息，两者用途不同。

### 6.2 可单独请求的身体动作

| 产品 | 身体动作 |
| --- | --- |
| 爬爬熊猫 | 摇头、向左看、向右看、挥左前肢、挥右前肢、举起前肢、交替爬行、同步爬行 |
| 恐龙 | 摇头、向左看、向右看、抬头、低头、摆尾、扭颈 |
| 摇尾小熊猫 | 摇头、向左看、向右看、摆尾、扭动身体/颈部表现 |

这些动作根据各产品机构编写，不会把同一组角度生硬套给三款产品。
方向性请求保持指定方向，不随机把“向左看”变成向右看。

在线对爬爬熊猫说“爬一爬/向前爬”可触发 6 轮交替爬行（每周期 800ms），说“双手一起爬”可触发 4 轮同步爬行（每周期 1200ms）。正常起始均约 5.6 秒收尾；每次有限执行。
完全离线时，“开心”从扩展玩耍类别选择，连续/组合触摸从三套回应选择，可能选到爬行动作；没有新增这些爬行短语的离线模型。

### 6.3 动作素材

| 产品 | 当前动作素材规模 |
| --- | --- |
| 爬爬熊猫 | 33 组表演剪辑、8 组身体动作、33 组互动剪辑（11 种事件各三套，含短爬行） |
| 恐龙 | 30 组完整表演、30 组短声音编舞、7 组怒吼变体、7 组身体动作、33 组专用互动剪辑，另有待机生命脉冲素材 |
| 摇尾小熊猫 | 34 组表演剪辑、5 组身体动作、33 组互动剪辑（11 种事件各三套） |

以上数量是编舞条目数量，不代表有同样数量的本地声音文件，部分身体指令与表演共用素材。
本轮新增内容、洗牌规则及完整目录见[动作库扩展](wzh_rich_motion_2026-10-16.md)。
触发了带本地声音的恐龙回应时，仍按实际声音名称和时长选择编舞；怒吼先正面仰头再进入后续变化。
素材保留不代表会定时播放，待机脉冲不再自动调度。

### 6.4 大幅度与平滑运动

两款熊猫一般编舞目标采用 1.85 倍增益，明确动作增加最多 8° 可见偏移，微小收尾保持默认位；恐龙在原幅度参数上继续增加目标行程。仍受每款机械限位约束，安静／温和状态缩幅。
三款继续使用连续同向插值与浮点输出，缩短移动和停留，最终运动指令变化上限为 400°/s；这是软件上限，不是实际带载速度。
两款熊猫头部左右看／摇头可达 8°～172°，恐龙 0°～180°。爬爬熊猫本轮重编排全部74个动作入口，71个动作头部与双爪均有明显参与；另外3个具名头部指令只动头。增加各轴错拍和临界阻尼语音跟随，爬行头部约30°～150°回看，双臂保持参考正弦周期。
动作结束回默认位后释放，静置不自行表演。恐龙身体指令取消额外慢放，长录音不再成倍拉长普通动作。
爬爬熊猫详见[整套灵动编舞及前后预览](wzh_crawl_lively_2026-10-16.md)；另外两款见[快动作说明](wzh_fast_motion_2026-10-16.md)。

## 7. 陪伴状态与恢复规则

| 状态 | 表演/本地叫声 | 主动交互 | 如何恢复 |
| --- | --- | --- | --- |
| 正常 | 有效互动后回应，空闲安静 | 触摸、感应、口令与联网对话 | 无须恢复 |
| 安静 | 暂停 | 可小幅无声回应；主动聊天仍可发声 | “醒醒”或明确唤醒 |
| 停止 | 停止并释放舵机 | 普通动作、触摸和情绪不能解除 | “醒醒”、本款专用唤醒词或 GPIO0 双击 |
| 休息 | 停止声音和动作，释放舵机 | 等待明确唤醒；目前直接释放，不另播入睡编舞 | “醒醒”、本款专用唤醒词或 GPIO0 双击 |
| 温和窗口 | 暂停自主表演，减小回应 | 轻柔回应，持续触摸可延长 | 窗口结束后按当前模式继续 |

停止与休息状态在本次上电中保持，尚未写入永久存储；重新上电回到正常模式。
安静模式用于减少主动打扰，不等于关闭扬声器或切断麦克风。

## 8. 电池、芯片温度与舵机保护

| 保护项目 | 当前条件 | 响应与恢复 |
| --- | --- | --- |
| 电池采样就绪 | 上电 RC 等待约 15 秒，再取得连续 3 次有效读数 | 未就绪时禁止舵机；采样失败重新锁定 |
| 低电量禁动 | 连续 3 次有效电压 ≤`BATTERY_LOW_MV`（演示 3.10V / 常规 3.30V） | 禁止舵机、暂停本地动作声音并清空待执行动作 |
| 低电量恢复 | 连续 3 次有效电压 ≥`BATTERY_RECOVER_MV`（演示 3.25V / 常规 3.40V） | 解除低电量限制，其他保护仍有效 |
| 严重欠压 | 连续 3 次有效电压 ≤`BATTERY_CRITICAL_MV`（演示 2.90V / 常规 3.00V） | 直接关闭舵机供电和整机锁存，不再播放提示或回中 |
| ESP32 芯片过热 | 芯片温度 ≥85°C | 禁止舵机；降至 ≤65°C 后解除过热锁 |
| 自由落体估计 | 连续 3 个加速度样本低于约 250mg | 释放舵机；连续 25 个有效近 1g 样本后解除 |
| 连续通电预算 | 连续通电达到约 60 秒 | 关闭舵机，至少冷却 5 秒 |
| 运动更新超时 | 已通电但约 500ms 未收到运动输出更新 | 锁定并释放；明确唤醒后允许重试 |
| 动作结束释放 | 有限表演或身体动作完成 | 停止 PWM 并关闭公共舵机电源；下一次允许的动作再开启 |
| 维护与关机锁 | 升级、启动硬件、录音测试、关机等阶段 | 抑制运动，不能由普通互动绕过 |

电池约每秒采样一次，电量百分比按 3.2～4.2V 估算，并非专用电量计的精确剩余容量。
每个板子的 `config.h` 用 `BATTERY_DEMO_MODE` 选择阈值：置 1 为演示续航优先，置 0 为常规保护；
量产前改回 0。
熊猫动作结束保留约 300ms 到位时间；声音随动期间可继续输出动作，随后按规则释放。

当前主板没有舵机电流、位置反馈、绕组温度或电池 NTC 接入 MCU。
因此，“动作后释放”和“超时断电”属于保护兜底，不能直接发现运动中的真实堵转；
85°C 保护测的是 ESP32 芯片温度，不代表电池、舵机或外壳温度。

## 9. 本地声音与 Audio Hub

### 9.1 本地音频库

外部 SPI Flash 保存动物叫声、环境音及其他已录入的 OGG/Opus 资源。
固件可识别支持的 NOR/NAND 芯片；当前原理图标注 W25N01GV NAND。
兼容旧 PNDA 目录，并具备新目录校验、文件读写、删除和擦除能力。

播放与在线语音共用唯一 AudioService，避免重复安装音频驱动。
当前未提供用户现场录音保存为新宠物声音的完整功能。

### 9.2 后台音频同步

Audio Hub 提供注册、激活绑定、状态查询、清单获取和声音下载，后台任务不阻塞主循环。
成功绑定后安排首次同步；开机与最近动作请求后的约 30 秒，以及动作、声音和在线对话期间均避让。
进入互动会中止后续下载读取，网络单次读取超时约 1 秒；手动请求保留到合适时机，失败退避重试。

同名文件追加新数据并验证后再替换条目，下载失败不先删除旧录音，网络读取期间不持有目录锁。
同版本清单也检查缺失文件；空、重复、越界或无效清单被拒绝。注册支持 200/201、原激活码、直接令牌及缓存绑定。
HTTPS 构建接入证书包验证；正式地址、服务端所有权和数据策略仍需实际配置。

目录 CRC、滚动槽及坏块处理不代表所有介质任意时刻掉电无损；NOR 单槽和 NAND 压实窗口仍需实机测试。
详见[整机优化及更新边界](wzh_product_polish_2026-10-16.md)。

模型或接入系统可以通过 MCP 调用设备功能。恐龙的产品工具前缀为 `self.dinosaur`；
两款熊猫均使用 `self.panda`，每台固件只注册对应产品实现。

| `react_to_user_emotion` | 在线对话中的情绪动作回应 |

| `sound_play` | 按名称或下标试听声音 |

重启、固件升级和资源下载地址等维护入口。动作请求返回是否接收，不代表机械动作已经实际完成。
擦除确认字符串和维护工具分类不等于已经具备家长权限管理。

动作、身体、情绪与模式工具默认保持原布尔返回；可传 `details=true` 获取请求接收状态和拒绝原因，不能将接收当成实物已完成。维护工具从普通模型发现列表移出，user-only 分组不等于家长身份认证。

## 13. 使用场景示例

| 场景 | 当前可提供的体验 |
| --- | --- |
| 没有网络时摸摸宠物 | 触摸回应，配合已有本地叫声与动作 |
| 用户来到附近 | 人体输入有效且招呼条件满足后，宠物观察或打招呼 |

| 联网后说“今天我很开心” | 云端对话，结合情绪与文字规则做开心回应 |
| 联网后说“我有点难过” | 对话陪伴与温和倾听动作；回应内容由云端角色决定 |
