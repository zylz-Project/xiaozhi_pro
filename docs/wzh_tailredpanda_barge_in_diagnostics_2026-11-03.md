## 已确认的实机事实

- 6 dB ADC 增益已读回 `reg16=0x01`，参考路由 `reg44=0x58`。所测播报窗口削顶为 0，
  DAC 参考有实际音频，不能再把问题归因于没有参考或 ADC 一直削顶。
- 用户没有开口时出现过 `echo_corr=48%`、候选 RMS 699，而否决门槛为 55%；
  因此相关性检查是启发式条件，不能当作“已经确认是独立人声”。
- AFE 原默认 `fixed_first_channel=true`、`fixed_output_channel=true`。对照关闭前者后，
  启动日志读到 false，但纯播报仍产生多个候选。它不是全部问题。
- 起播短片段中，处理后音频曾与原始麦克风高度相关，幅度接近 4 倍；更长片段的独立
  对齐表明 AEC 确实工作，扣除输出 4 倍增益后，所测分段能量衰减约 7～28 dB。
  这是录音分段 RMS 比的估算，不是标准化 ERLE 验收，也不能据起播片段认定 AEC 全程关闭。
- 用户确认一轮全程没有说话，后续另一轮按要求在播报中说话并回复“已说”。
  后者只有近似时间标记，不能宣称每一帧都有精确人声标签。

## 限时本地采集

新增开关均默认关闭：

- `AUDIO_DEBUG_PACKETIZED`：在原 UDP 调试器上增加 XDBG 格式；原裸 PCM UDP 格式保持默认。
- `AUDIO_DEBUG_DURATION_SECONDS`：5～120 秒，默认 60 秒，从首个成功发送开始计时。
- `VOICE_BARGE_IN_SHADOW`：只记录候选，不调用取消播报的应用回调；只有回复监测期间发送音频。

原始数据为实际送 AFE 的重采样 MR；另一路为编码前的处理后单声道 PCM 和当前 VAD。
socket 等网络接口存在后再创建；两路共享稳定生命周期，发送使用 `MSG_DONTWAIT`，
固定报文缓冲 672 字节。UDP 可丢包，接收器必须检查序号和采样位置。

| XDBG v1 字段 | 格式 |
| --- | --- |
| magic / version / stream / channels / flags | `4sBBBB` |
| sequence / sample_rate / sample_position | 3 个小端 uint32 |
| device_us / frames / payload_bytes | 小端 uint64 / uint16 / uint16 |
| PCM | 最多 640 字节，int16 小端交错 |

头部共 32 字节。stream 0 是原始输入，stream 1 是处理后单声道；flags bit0 是 VAD。
`device_us` 是调用时刻，不能当成硬件采样时刻；离线分析仍需对齐 AFE 延迟和分包边界。
接收器验证格式，按采样位置补零并报告丢帧，拒绝重复/倒序包；设备时钟回退时终止采集，
避免把重启前后的录音混成一段。

```sh
python3 scripts/audio_debug_capture.py --source DEVICE_IP --output /tmp/panda-trace
```
