# 三款动作流畅度、自身震动误触发与日志修正

日期：2026-10-16。适用：爬爬熊猫、摇尾小熊猫、恐龙。
本轮针对用户新日志中的迟缓、停顿、动作期间加速度候选和长录音持续带动舵机进行修改。

## 日志说明了什么

- `23.995～24.645s` 多次出现 `picked_up accepted=0`：加速度计把运动当作拿起候选，但这些候选没有被控制器接受，不能把它们说成已经启动了拿起动作。
- `48.565s` 的 `settled accepted=1` 确实提交了后续回应。没有当时的操作记录，不能断言用户没有放下玩具；需要消除自身运动留下候选或计数的风险。
- 触摸发生在约 `21.765s`，普通动作与声音随动持续到约 `47.545s`。旧控制循环会在动作结束后继续跟随长 Flash 录音摆动，直到播放结束。
- 旧两款熊猫的每个移动关键帧都用零速度起止的五次缓动，并按 80°/s 峰值延长时间；相同姿态也至少停 420ms。虽然幅度大，逐段减速和停顿使动作显得迟缓、机械。
- `gentle=1` 后变成 `gentle=0`，可能在动作中途扩大目标偏移。这轮保留每个动作开始时的温和上限，防止计时到期时突然放大。
- 电池原始值从约 3.55V 降到约 3.25V，存在供电压降迹象。这段日志没有显示复位或动作保护触发，不能仅凭电压变化断言卡顿来自供电。

## 本轮代码修改

### 连着运动，减少机械停顿

两款熊猫改用带相邻帧时间权重的单调三次 Hermite 插值；恐龙原有衔接也改用同一时间权重计算。
同一方向的相邻关键帧共享经过速度，不再每到一个中间姿态就先刹停再启动。
反向、明确停留和最终回中仍自然减速，并限制在关键帧两端之间，避免曲线过冲。
各轴使用同一段时间进度，保留头、前肢或尾巴的协调。

三款移动段最低 220ms，实际时长还受到位移和速度预算约束；原有段落时间按 0.62 调整。
明确停留按原时长的 0.35 调整并限制在 80～240ms。
最终软件指令限速统一为 160°/s，移动段以两倍平均行程预算峰值；这些是指令限制，不是实测舵机速度。
原有动作幅度、轴方向、机械软件限位、爬行步态和温和/安静 60% 偏移保留。

熊猫控制循环和恐龙插值段使用 20ms 周期调度，减少把计算、日志耗时累积进每个周期造成的节奏漂移。
熊猫调度在长时间落后时重置周期，避免连续追赶写入。

### 保留小数角度，减少输出小台阶

熊猫输出和恐龙的逻辑姿态、插值、最终输出改用浮点角度，直到共享 ServoOutput 才转为 PWM duty。
不再先把角度取整为 1°，再截断成整数微秒。现有 13 位/50Hz PWM 的 duty 粒度约对应 0.22°，
它只代表电信号分辨率，不能证明实物有同样的精度。
整度装配接口仍可用，默认角度、脉宽范围和引脚不变。

### 动作中暂缓姿态陪伴回应

加速度计仍每 20ms 采样，更新状态并独立检测自由落体。
舵机上电期间和释放后 600ms，暂缓拿起、摇晃、翻面、放稳这类宠物动作请求，并清除相关候选和累计值。
停稳后重新接受真实互动；控制器也拒绝动作忙碌/上电期间的姿态动作请求。
这避免电机震动生成候选，再在动作结束后补演一次。

这不是关闭加速度计：自由落体仍经过连续样本检测并立即释放舵机，传感器读错重试也保留。
代价是正在做动作或说话随动时，摇晃不会另行启动宠物姿态回应；触摸、语音停止等入口仍可用。
单个加速度计不能可靠区分每一种外力和电机运动，也不能精确测量接触地面或拿起高度。

### 长录音不会延长触摸表演

触摸与姿态使用各自有限编舞，结束后回中、释放舵机。
已有 Flash 原始录音可以继续播完，但不会仅因录音还在播放，就继续启动/维持离线随声摆动。
在线实际说话时继续保留声音随动与内容动作；恐龙显式声音表演仍保留自身匹配编舞。
无人互动、开机后、对话结束后都不增加定时表演。

继续只使用外置 Flash 的现有动物录音，不添加合成叫声，不剪短或改写用户原录音。
连续触摸仍可替换动作，繁忙时不积压录音；停止、休息、安静与进入对话仍会取消本地播放。

### 常规日志更少，保护变化仍明确

| 信息 | 当前输出 |
| --- | --- |
| 动作开始 | INFO：`clip=...` 或恐龙 `Interaction=... motion=...` |
| 互动选声 | INFO：`Interaction=... external Flash sound: ...` |
| 有效姿态事件 | INFO：`Interaction=picked_up/shaken/...` |
| 电池摘要 | 第一条有效采样和之后约每 30 秒一次；仍每秒采样、判断保护 |
| 欠压、过热、跌落 | 状态变化时 WARNING，说明保护原因并释放舵机 |
| 初始化、休息、维护等状态 | 状态变化时 INFO |
| 舵机角度、加速度原始值、拒绝候选、触摸原始码、每秒电池原始值 | DEBUG，正常 INFO 日志不刷这些行 |

重复释放已断电舵机时不再重复写 GPIO/PWM stop。SDK 的启动、网络和系统内存统计仍按原规则输出。
需要原始诊断时，可在 ESP-IDF menuconfig 中允许 DEBUG 最大日志级别，再针对相应标签调试；一般使用保持 INFO。

## 下次实机体验重点

先分别单触四点，观察动作及时开始、到达明显姿态、顺畅回中；声音还在播放时，舵机也应结束本次动作并释放。
再测试静止时拿起/摇晃，以及舵机动作期间的震动，确认不会在结束后自行补演。
最后验证在线说话随动、停止/休息、播放中唤醒和保护。

本轮没有烧录、连接串口或完成机械验收。若新版仍明显卡顿，需要同时核对舵机供电压降、机构干涉、舵机死区/齿隙与负载；
软件轨迹平滑不能代替电源和机械检查，源码也无法反馈舵机实际角度。
