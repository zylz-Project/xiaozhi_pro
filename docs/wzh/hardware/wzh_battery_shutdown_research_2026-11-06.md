# 陪伴产品电池保护与关机调研（2026-11-06）

目的：核对成熟产品怎样处理低电、减载、正常关机与强制断电，并指导本工程的关机播报修复。
参考范围是厂家公开手册与芯片原厂资料。消费产品未公开的固件算法、电芯阈值和延时不作猜测，
也不把这些产品的电压或按键时间直接套到本产品。

## 芯片保护与软件体验的分工

[TI BQ2970 原厂说明](https://www.ti.com/product/BQ2970)将单节电池的过充、过放、
充电/放电过流和短路检测列为电池保护器功能，并提供外部保护 MOS 驱动。
这里将它作为保护职责的例子，不是已经为本板选型或确认必须换用该器件。

本工程图纸使用的 ETA9742 是充电/升压器件。原厂资料列出了芯片热调节、热关断和短路
打嗝保护，STAT 用于充电状态，BST 用于升压/充电/空载状态。引脚表中没有独立的
RESET/KEY 长按强制关机输入；原理图里的同名网络不能直接解释成该芯片的功能。
因此，当前“播报半句断电”不能仅凭现象归因于 ETA9742 的长按定时器。
来源：[ETA9742 V1.1 原厂手册，第 2～3 页](https://www.eta-semi.com/wp-content/uploads/2022/03/ETA9742_V1.1.pdf)。

这些芯片功能不能代替整机验证：还需要确认实装电芯/保护板、充电电流设定、线束与连接器、
升压器负载余量、可触及机构和温升。现有图纸没有向 MCU 提供电池 NTC 或舵机电流/角度反馈；
ESP32 的温度读数和动作计时释放不代表已经测到电池温度或真实堵转。
本板接口证据及限制见[已有硬件核对](hardware_review.md)。

## 建议采用的分层策略

下面是结合本工程的设计建议，不能解释为已获整机安全认证。

1. **普通低电**：确认低电后提醒，先禁止高耗电动作；稳定恢复且有足够余量后才解除限制。
   需要连续确认、迟滞和负载观察，避免一次动作压降就反复“低电—恢复”。
2. **正常关机**：一次性受理长按，拒绝新的互动；有限归中并关闭舵机电源；完成旧会话清理，
   播放本地关机语音，确认本次语音的生产及输出结束，最后释放电源锁存。
3. **正常低电自动关机**：若后续需要该功能，应在仍有收尾余量时触发，使用独立的策略和
   验收条件。不能一直拖到硬件保护点才要求播放完整长句。此项本轮没有新增电压阈值。
4. **确认临界欠压/硬件保护动作**：优先关闭负载和供电，不等待语音或舵机归中。
   软件按有效样本确认后执行，硬件保护的响应由实装保护电路决定。
5. **任务卡死或解码失败**：正常关机有总等待上限；超时应明确记录未完整播报，并取消残留
   请求。设备不能因等待一个失效音频任务而无限维持电源。

## 与本工程的对应关系

- 三款当前均为 `BATTERY_DEMO_MODE=0`：低电 3300 mV、恢复 3400 mV、临界 3000 mV。
  这是当前代码值，本轮不改变，不表示已确认适合实装电芯或在该电压下必定还能完整播报。
- 普通保护使用时间中值与连续确认，恢复要求静置；临界保护另看连续有效的实时电压样本。
  现有采样周期为约一秒，不应把软件路径说成硬件毫秒级保护。
- 现有电池百分比来自静置电压估算，不能把其 0%/100% 当作精确电量或保护阈值。
- 低电提醒目前等待空闲、播放结束且非录音/维护时执行，连续长对话中可能延后。若产品
  需要限时低电退出，应另定句间提醒/退出策略并验收；本轮没有增加强行打断对话的规则。
- 本轮补齐关机归中等待期间的电池检查；播报等待期间也继续采样。确认临界欠压后走
  原有无语音、无归中等待的断电路径。
- 出厂资料应明确普通长按的反馈与松手方式，最终电源锁存由软件控制；是否存在外部
  按键/接口板直接断电，需要沿实装线路测量，不能只根据网络名推断。

## 本次关机播报修订

关机文案为“我要休息啦，下次再一起玩吧！”，熊猫音包约 3.13 秒。
旧代码存在固定 700 ms 的兼容路径；启用音包的路径也存在把取消后空队列误当成播完的风险。
此外，“休息”属于本地控制语义，关机期间仍接收本地口令会产生清空播放队列的入口。
这些是源码确认的风险；没有新实机日志时，不能把其中某一条宣称为本次实物故障的唯一根因。

修订后的处理：

- 三款使用同一个有界播放工作任务，关闭替换音包也不再恢复固定 700 ms 等待。
- 关机标记从入口生效，复用板级输入门控拒绝新唤醒/本地命令/重新进入会话；清理完成后
  关闭语音检测，再请求关机语音。
- 启动语音通过应用任务排在 `StopInteraction()` 已排队的清理之后，不把 2.4 秒归中等待
  当成应用清理完成的证据。
- 完成条件绑定本次请求和播放 generation，并检查生产结束、队列及在途输出排空和短尾部
  时间；全局排空计数变化不单独用作本句播完的证明。
- 延迟取消允许一次重试，共用原八秒上限；超时后旧应用回调和等待中的生产者都失效。
- 保留临界欠压优先切电，电压阈值、原音频、引脚和舵机保护参数不改。

## 必须取得的实机证据

正常长按（触发后松手、持续按住分别测试）、在线播报时关机、离线声音时关机、低电时关机、
多次开关机、主任务延迟和升级/重连边界。记录以下时间点及实际音频：

`Power-off requested` → 舵机电源关闭 → 关机语音开始 → `Shutdown speech completed`
→ `Power latch released`。

同步测 BAT、5V_Servo、3.3V 与 GPIO7：如果日志中的锁存释放早于完整语音，是软件时序；
如果 GPIO7 仍维持而供电先消失，应继续排查自锁外围、升压/电池保护、连接和供电余量。
受控欠压测试由硬件人员在台架进行；正常播报验收不能替代电芯与整机安全测试。
