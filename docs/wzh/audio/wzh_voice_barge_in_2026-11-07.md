# 大熊猫与恐龙：对话人声打断（2026-11-07）

> **2026-11-08 配置更新：**三款产品的默认构建名现在也启用人声打断及 NSNet2。下文记录的是 2026-11-07 的构建和测试结果，其中“普通版关闭打断”等描述仅适用于当时的固件。已有 `-barge-in` 构建名继续保留；升级旧普通版时需同时更新 app 和 assets，不能仅更新 app。

大熊猫、恐龙现在使用小熊猫现有的普通人声打断链路。新增两个独立构建入口，普通版显式关闭自动打断；本轮没有改变小熊猫的配置。三款方案仍是需要分别实机验收的候选。

## 待实现：服务端转写确认后打断（2026-11-10）

当前仍为本地 AEC / VAD 等检测通过后立即停止播放，再开始上传用户语音，**尚未实现“识别出文字后才停止”**。本地检测到的声音和服务端识别出的有效用户文字是两个不同条件；旧会话迟到的 STT、空字符串、纯标点、设备自身声音以及识别超时均不能被当作确认。

要满足该需求，服务需要在保留当前回答的同时接收候选语音，并返回可关联到该候选的识别结果。现有小智协议文档描述 `listen`、`abort` 和 `stt`，但没有保证服务支持独立候选识别或提供可关联的候选 ID；不能仅将 `AbortSpeaking` 移到现有 STT 回调，否则当前逻辑不会先上传语音，可能一直等不到转写。需要先确定所用服务是否提供相应能力，并在 WebSocket / MQTT 两种传输、掉线、超时、回声与噪声场景中验证。

未确认服务端能力之前，本轮保留现有打断行为，不把本地声音检测或无关 STT 当作服务端确认。参考[小智 WebSocket 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)和[MQTT/UDP 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/mqtt-udp.md)。

## 构建入口

| 产品 | 人声打断版 | 普通版 |
| --- | --- | --- |
| 大熊猫 | `wzh-crawlpanda-barge-in` | `wzh-crawlpanda` |
| 恐龙 | `wzh-dinosaur-barge-in` | `wzh-dinosaur` |
| 小熊猫（已有） | `wzh-tailredpanda-barge-in` | `wzh-tailredpanda` |

```sh
source /path/to/esp-idf/export.sh
python3 scripts/build.py wzh_crawlPanda --name wzh-crawlpanda-barge-in
python3 scripts/build.py wzh_dinosaur --name wzh-dinosaur-barge-in
```

优先使用 ESP-IDF 6.0.2；本机只有 6.0.1 与旧版 5.5.4，本轮使用 6.0.1。
两个新变体仍使用各自原有 ESP32-S3 板选择、16 MB Flash 和分区表、唯一 `DECLARE_BOARD`，无需增加 Kconfig 板选择或 CMake 板源分支。`build.name` 分别带 `-barge-in`，也是设备上报的 OTA 板名；产品 `type`、配网热点前缀、引脚和本地 MCP 名称不变。大熊猫仍用“你好小安”，恐龙仍用“小龙小龙”，没有套用小熊猫的唤醒模型。

打断版启用 NSNet2、WebRTC VAD 和 USB Serial/JTAG 日志，关闭服务器 AEC、音频采集调试与 shadow 模式。每次切换构建均由规范脚本重新生成配置。安装打断版须同时更新其 app 与 assets，普通版资源缺少 NSNet2，不能只换 app。普通版及打断版固件分别保存于 `dist/wzh-barge-in-20261107/`。

## 接入与运行行为

- 两款 `GetAudioCodec()` 按 `USE_VOICE_BARGE_IN` 给唯一 ES8311 实例启用 DAC 播放参考。打断版捕获 M/R 双通道，使用共享 codec 已有的 6 dB ADC 增益、双槽写入与恢复后参考路由；普通版保持单通道采集。24 kHz 硬件采样率和各板供电参数不变。
- 复用公共 FD AEC → NSNet2 → WebRTC VAD，不复制另一套音频任务。NSNet2 的 512 样本、VAD 的 160 样本及编码的 960 样本沿用已有跨帧缓冲。在线期间暂停附加 MultiNet，待机恢复。
- 自动打断继续检查新鲜播放参考、原始 ADC 削顶、起播稳定期、持续语音、能量与回声相关性。缺模型或参考异常时拒绝自动打断。会话中的 WakeNet 事件不能绕过这些检查。
- 确认前最多保留 720 ms 压缩人声前缀；主任务复核令牌后停止本地播放、清旧回复并继续当前采集。旧回复须等新非空 STT 后才可重新接管。WebSocket 和 MQTT/UDP 使用已有 abort／auto-listen 消息。
- 保留双击进入／完整退出对话以及本地声音与动作的现有优先级。没有移植小熊猫专用素材响度表或扬声器 EQ；它们不是人声打断的依赖。

## 软件自审

自审以修改前工作区快照为基线，避免将已有的动作、系统播报与关机工作混入本次变更。主要检查：

1. 构建配置到 codec 的实际连接：对三款板的生产 `GetAudioCodec()` 方法分别编译开／关两种配置，检查参考标志、采集通道、24 kHz 及单实例复用；检查各变体的模型、唤醒词、调试关闭和普通版回退配置。
2. 复用链路的已有回归：纯相关回声不触发、参考丢失／采集停顿／削顶撤销候选、失效事件不取消新回复、首字缓存有界有序、会话唤醒词不绕过确认、取消后旧回复隔离及公共双传输消息约定。
3. 构建产物：分别构建两款普通版与打断版，核对最终 Kconfig、唯一板选择、Flash／分区、模型清单和镜像尺寸。验证结果完成后记录于下文与交付清单。

验证结果：打断专项 20 项通过，四个规范构建均成功，格式检查与 `git diff --check` 通过。全量主机回归 **288 项通过**（105.562 秒），包含普通人声打断、神经前端、会话切换、系统播报、关机及模型打包检查。

## 仍需实机验收

本轮不含烧录或新样机声学结果。小熊猫既有方案也没有完成可靠性验收，软件通过不能证明新机壳中没有自打断或漏检。需要对两款分别检查：

1. 无人开口的长故事、含唤醒词播报、人声音乐与短提示；覆盖常用／最高允许音量、动作开启／关闭及句间停顿，不能出现自身播放引起的取消。
2. 正常距离开口、低声短句、句间插话与连续多轮，记录打断成功率、延迟和首字／新问题识别；始终无法打断也不算通过。
3. 双击退出再进入、静音、参考异常、断网重连、正常收音／播放／待机唤醒／本地命令恢复；核对无 AFE 溢出、持续帧超时或看门狗告警。打断版会话唤醒词经过相同确认，前端异常时使用按钮退出。
