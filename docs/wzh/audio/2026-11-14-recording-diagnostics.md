# 2026-11-14 复刻录音和播放诊断

适用于三款共用 WZH 语音和 BLE 服务的板型。爬行熊猫第二次日志中，第一次录音的
VAD 有效人声为 4.98 秒，低于现有 5 秒准入门槛；第二次录音成功。本次保留这个门槛，
先修正录音状态、用户提示和故障定位，不以降低门槛代替音色质量验证。

- `voice_record` 的新客户端可以选择 `statusPoll:true` 并查询
  `voice_record_status`；云端操作可能超过旧事件监听窗口，查询不会重试创建。
  旧客户端仍可接收事件。小程序在设备报告 `processing` 前不会宣布录音结束；
  弹窗关闭不会取消或忘记进行中的设备任务。
- 有效人声不足时提供可执行的重录提示。设备在播完结果提示前仍保持任务占用，
  查询可提前展示已知失败原因；UI 不会提前允许再次创建。
- 每个 HTTP 流记录内容无关的 `Ali stream stats`：字节和事件数、单次读取及
  解析/送入播放环节的最长耗时、简要失败阶段。不记录密钥、语音或服务端原文。
  读取耗时可能包含云端、网络、驱动及任务调度；处理耗时包括播放缓冲背压和
  调度，均不能单独定因。播放端原有 `underruns` 也不是直接的声学停顿时间。
- 电源键异常新增前一轮任务工作时间、任务延时区间和看门狗调用时长，帮助区分
  长间隔发生在何处。时间为毫秒级，不证明 CPU 实际执行时间或精确阻塞根因。
  保留采样异常后必须确认释放才能长按关机的安全逻辑。

## 各产品实机验证

分别测试 BLE 新旧客户端兼容、录音不足/足够、关闭重开弹窗、断连后检查音色列表、
正常音色和复刻音色的短/长回复、安静环境和真实人声打断、动作与电源键。长按关机
还应验证连续有效采样、ADC 异常、按住时采样间隔过长以及松手后重新按住的情况；
不应通过跳过未知采样来推断长按。音色创建、删除和 OTA 需覆盖断网、断电、NVS 和
结果不确定的恢复；不得自动重试可能已在云端生效的创建。

同时记录 Wi-Fi 条件、固件版本、`Ali stream stats`、`Ali PCM buffer underruns`、
神经处理耗时、`Power key sample invalid`、内部和 DMA 堆总空闲/最大连续块，以及
任务栈高水位。`CONFIG_WZH_MEMORY_DIAGNOSTICS` 会增加开销，只在诊断版本启用。
最大连续块与总空闲不等价；按区域汇总的历史最低值也不一定在同一时刻发生，参见
[ESP-IDF 6.0.2 堆内存 API](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32s3/api-reference/system/mem_alloc.html)。
在定位云端、网络或设备瓶颈并完成三板型实测以前，不应声称已消除卡顿、调度停顿
或内存不足。未经实机验证的 PSRAM 工作栈/Flash 调度器依旧是实验开关。
