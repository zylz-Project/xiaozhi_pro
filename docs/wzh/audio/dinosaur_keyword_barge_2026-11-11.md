# 恐龙对话关键词确认打断（测试版）

根据实机反馈，舵机噪声可让 VADNet 和声音能量门限误判；设备仅靠人声概率无法证明是用户讲话。乐鑫 [MultiNet 文档](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32/speech_command_recognition/README.html) 描述了基于 16 kHz、16 位、单声道 AFE 输出的离线命令识别，命中的是预设词而非任意转写。其识别并非绝对无误；播放回声、舵机声、距离、方言、较短的“停”和“你好”都可能造成误识或漏识。此前实测 NSNet2 与 MultiNet 同时运行曾造成实时预算不足，因此恐龙该测试关闭额外 NSNet2 神经后处理，仍保留全双工 FD AEC、播放参考及基础 VAD；是否满足处理时限和语音音质必须实机验证。

恐龙普通构建及 barge-in 构建启用 `WZH_DINO_KEYWORD_BARGE_IN`，大小熊猫保持原设置。播放时多路关键词识别持续运行：只检测到近端声音不会自动打断；在回声参考有效且最近三秒内已有近端候选的条件下，识别到预设词才进入已有打断流程。候选过期会失效并可重新生成。接受的词包括“小龙小龙”、原有“停下”等停止词，以及“停、停一下、等一下、别说话、别说了、先别说、你好、我有问题、我要说话”。不在词表里的任意说话不会触发；长句开头先说关键词再说内容。回声消除不是声纹认证，无法保证完全过滤设备自身播报或误触发。

为避免识别词尾时丢失开头，恐龙该构建将压缩后音频前缀从 720 ms 扩为最多 1.92 秒，仍受已有发送队列容量约束；断网、打断、录音复刻与回复隔离沿用原机制。若 MultiNet 模型或词表初始化失败，保留 WakeNet 和正常对话，普通关键词不可用；仅可尝试唤醒词打断，不能改为未确认的人声自动打断。词表加入资源包，程序与 `generated_assets.bin` 必须同时烧入。注意日志 `Dino keyword interruption accepted` 表示本地条件通过；`Dino keyword ignored` 表示没有近期有效候选，不代表云端已识别出文字。

实机对照至少包括静音及舵机连续动作期间无用户讲话、每个关键词分别近讲/远讲/轻声、语音与扬声器叠加、自身播报含关键词、普通非词表语句、连续会话/网络重连、唤醒和音色复刻；还需观察 AFE 处理超时、内存、看门狗、音质。不能以软件测试声称现场零误触发或识别率已达标。

软件自查：367 项全量主机测试通过；恐龙 `wzh-dinosaur-barge-in` 使用 ESP-IDF 6.0.1 构建通过，最终 `sdkconfig` 确认恐龙板、关键词开关、WakeNet 和 MultiNet 已启用且 NSNet2 未选；资源包可检出 9 条新增词及 `wn9_xiaolongxiaolong_tts`。未烧录、未进行实机录音或声学验证，不能据此确认命令词注册成功、识别准确率、端到端延迟或处理性能。
