# 小熊猫产品音频：全链路候选版（2026-11-04）

本轮覆盖当前工程的提示音、配对录音、外置 Flash 音效、联网 TTS／音乐的公共播放链路，
以及麦克风上传编码。目标是改善素材响度差异、起止杂音和格式处理，保持可用音量。
代码、数字信号与跨板构建验证通过后才能交付候选固件；**尚未完成本轮实机试听，不能据此
认定成品音质或普通人声打断已达标**。

用户不清楚喇叭和音腔规格。本轮没有提高模拟功放增益、取消保护或盲目提升低频。
ES8311 的 24 kHz 物理采样率、音量持久化键、120 Hz 高通、峰值上限和电源策略保持原值。

## 调研依据与取舍

- [Ogg Opus 标准 RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html)规定以 48 kHz
  计数的 granule／preskip、输出增益及原始采样率字段的语义。本地文件按这个时间轴解码、
  裁切后转换到硬件采样率；原始录音采样率不再直接决定 Opus 解码配置。
- [EBU R128](https://tech.ebu.ch/docs/r/r128.pdf)说明综合响度与峰值测量的不同用途。
  本轮借用响度测量方法，候选素材目标 **−16 LUFS 是产品选择**，不是其广播目标，也不声称
  R128 合规。静态校准避免逐帧自动增益反复起伏；最终增益仍受原有扬声器保护约束。
- [Espressif 音频编解码库](https://github.com/espressif/esp-adf-libs/blob/master/esp_audio_codec/README.md)
  和本地 SDK 的 `esp_opus_enc.h`提供 Opus 比特率／复杂度配置。麦克风保留 16 kHz 单声道、
  60 ms、AUDIO 模式、VBR，明确为 32 kbps、复杂度 3，采集重采样质量由 2 改为 3。
  这是算力和上传带宽的候选预算；AUTO 原码率不固定，不能直接声称码率比此前更高。
  原 AUDIO 模式下 DTX 本就不生效，因此关闭配置项不等于修复了已证实的丢字。
- 官方音乐服务在用户日志中输出约 27.4 kbps 单声道。设备端没有经过确认的服务端高码率
  控制接口；本轮没有改变这个音源。提高解码采样率或 EQ 不能重建压缩时丢失的细节。
  参见[上一轮音乐反馈](wzh_tailredpanda_music_feedback_2026-11-04.md)。

## 实现范围

| 路径 | 本轮处理 |
| --- | --- |
| 系统提示音 | 原始 Opus 不重编码；正确处理 preskip、末页截尾、头增益；已知素材独立响度校准 |
| 14 段内置配对录音 | 使用同一格式处理与校准；原录音、手调动作和素材目录不改写；截取按可听采样计时 |
| 外置 Flash 音效 | 同一解码、格式增益和输出保护；未知素材默认附加增益为 0，可用下述工具准备新素材 |
| 联网 TTS／音乐 | 保留已有清晰度 EQ 和 1 ms 前瞻平滑限幅；回复结束补齐 DSP 尾部并短时淡出；官方下行编码不改 |
| 中止／退出 | 单一输出任务从最后实际输出采样淡出；取消时丢弃旧前瞻内容，避免串入下一轮 |
| 录音测试回放 | 保留全部录音包；标记独立开始／结束，同样重置解码历史并平滑收尾 |
| 麦克风上传 | 上述明确的编码预算、质量 3 重采样和复用缓冲；ADC 增益、AEC／NSNet2／VAD／打断门限不改 |

`AUDIO_PRODUCT_QUALITY` 默认关闭，依赖 S3 与 PSRAM，仅两个小熊猫变体默认启用。
板级校准通过可选 `Board::GetAudioSourceGainQ8()` 提供，核心不依赖小熊猫具体类型。
校准只匹配已知素材的长度和 64 位指纹；未知或改变过的文件不套用旧增益。
指纹不是安全校验 API，生成器检查已知集合内的碰撞。

源增益在浮点域、滤波和限幅前应用，避免先在 int16 上放大削波。校准选择范围为
−4～+6 dB，30 段实际校准也在这个范围内。独立文件开始时重置 Opus／输出转换器和扬声器 DSP，
每包之间不重置。正常结束先处理 1 ms 零输入以输出前瞻剩余，再从最后采样作至多 5 ms
平滑淡出；有输出重采样的已标记结尾补入 5 ms 零输入排出 FIR 尾部。没有新增第二个播放器、
I2S 驱动或主循环中的等待。

收尾由扬声器任务执行并参与排空计数。TTS stop 在解码进行中时不会提前结束已排队 PCM，
取消优先于下一轮排队音频；结束标记在最终解码失败时仍交给输出任务。队列仍有界，旧会话
generation 检查仍在。新增容器元数据只在本地传递，不进入 WebSocket 或 MQTT/UDP 的线协议。

当前 Ogg 解复用不是完整通用播放器：没有新增 CRC 校验、链式／多路流或随机寻址支持。
本轮验证对象是现有单流素材，不声称新增了通用网络媒体兼容性。

## 素材生产工具

重新生成本地校准表（需要 FFmpeg；不改写录音或动作目录）：

```sh
python3 scripts/audio/build_tailredpanda_audio_calibration.py
```

逐文件测量见[30 段校准表](../../data/tailredpanda_audio_calibration.json)。
生成的 `audio_calibration.inc` 不要手工编辑；更换原始素材后必须重新生成。

为后续导入准备单独输出文件：

```sh
python3 scripts/audio/prepare_product_audio.py master.wav --output prepared.ogg
python3 scripts/audio/prepare_product_audio.py existing-opus.ogg --output calibrated.ogg
```

现有 Ogg Opus 只调整头增益和对应页 CRC，保留压缩负载、preskip、时间戳；其他输入由
FFmpeg 一次编码为 48 kHz 单声道 Opus，默认 64 kbps、复杂度 10、20 ms VBR。
不要用低码率文件作为“升级母带”：重新编码不能恢复细节。脚本不覆盖原文件，已有输出需要
`--force`；输出附带 SHA-256 和测量 JSON。这个导出工具优先约束素材真峰值，区别于已知
内置素材在固件保护前的有限浮点增益。它不会自动写入外置 Flash 或改变官方音乐服务。

## 验证与自审

- 最终主机测试 256 项通过，包括实际生产代码的 preskip／截尾／增益、分块读取、解码器重置、
  转换失败、空结尾、generation 失效、取消优先、前缀等待中取消、收尾排空通知、解码进行中
  收尾、截取恰好落在包边界和包内的行为。
- 新音频、打断和扬声器保护测试另用 AddressSanitizer／UndefinedBehaviorSanitizer 运行，
  三组共 39 项检查通过，其中包含配置检查。
  这些是主机替身调用生产方法，不是 ESP32 时序或完整系统并发的证明。
- 现有 16 段中文提示音与 14 段配对音频使用生产解复用器、主机 libopus 实码流解码：
  **30/30 的裁切采样长度与 FFmpeg 一致**，每段一次起始／结束；去掉 6.96～60.75 ms
  的编码前后填充。原始录音和配对动作目录未改写。
- 将已解码素材送过生产扬声器 DSP，对照上一版保护器：响度差 −2.72～+6.00 LU，
  中位数 +0.73 LU，均值 +1.52 LU；最大样本幅度 27524，没有 int16 满幅样本。
  个别原本偏响素材适度降低；不能把集合均值当作每段的响度保证。
  这项对照采用 FFmpeg 的 24 kHz 转换，不是 ESP 硬件重采样或扬声器测量。
- 自审修正：容器采样率语义、跳过全部样本时不误记解码失败、失败 EOS 不遗漏收尾、空队列
  收尾重启排空通知、取消期间输出旧尾部、正在解码时提前收尾，以及截取边界漏发结束标记。
- 构建结果、二进制大小和校验见交付包的 `review/validation.json` 与各变体 `manifest.json`。
  小熊猫普通版／打断实验版、恐龙、爬爬熊猫、ESP32-C3 共 5 个变体构建通过。
  最终全量测试在全部构建结束后运行；中途与芯片切换并行的测试曾因依赖重建临时缺少
  `cJSON.h` 失败，未作为验收结果。
  本机仅安装可用的 ESP-IDF 6.0.1，未冒称已在要求优先的 6.0.2 上验证。

## 仍需实机确认

本轮没有连接可用 USB 串口，未烧录。需要同一音量比较普通播报、齿音、短提示音、
大动态音乐、14 段配对录音、外置音效，以及开始／结束／双击退出后的声音；同时核查
唤醒、收音、断网重连、AEC 和近距离普通人声打断，观察功耗、掉电与神经前端耗时。
增加编码复杂度的实时余量必须用设备日志验证。打断功能继续标记为实验，普通版作为对照。

硬件规格未知，数字样本不削波不能排除功放饱和、喇叭失真或音腔共振。本轮没有声压、
频响或 THD 测量。官方低码率音乐源也仍是约束，需要高质量同曲音源在相同声压下对照后
才能判断成品音质；固件不能替代这个验收。
