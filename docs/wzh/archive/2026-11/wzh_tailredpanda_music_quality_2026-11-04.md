# 小熊猫音乐音质：调研、实现与自审（2026-11-04）

**实机状态更新：用户已烧录，音乐主观音质仍不满意。最新日志的 27.4 kbps 音源分析和
后续对照见[音乐实机反馈](wzh_tailredpanda_music_feedback_2026-11-04.md)。下文保留首次候选记录。**

用户反馈原曲录音发闷、沙哑或破音，要求保持足够音量。本轮针对输出限幅的增益突变做可量化
修订，并补足输入音质指标；尚未在样机试听，不能宣称所有音质问题已经解决。

## MCP 与实际音频路径

日志中的 `% search_music...`、`% play_music...` 是 `Application: <<` 文本；在代码中该日志
来自服务端的 `tts/sentence_start`，它本身不是本机 MCP JSON 调用记录。全工程没有注册这
两个名字的设备端工具，因此判断它们来自服务端工具流程；仅凭这两行不能确认具体云端插件
实现、源文件或转码配置。

设备收到的声音仍经 `OnIncomingAudio` → 原 Opus 解码队列 → 单声道 PCM → 24 kHz ES8311
输出。`type=mcp` 只分发工具协议；它不承担这条二进制音频的解码。两种网络协议仍按服务器
协商参数接收音频。不要因为文字出现歌名、歌词或“play_music”，就从助手文本执行控制或
擅自更换时钟/均衡器；本轮没有这样的文本控制。

## 调研与取舍

- [Opus RFC 6716，§3.1/Table 2](https://www.rfc-editor.org/rfc/rfc6716.html#section-3.1)：
  TOC 包含编码模式、带宽和单/双声道。协商的解码采样率不能证明原曲频宽；例如 24 kHz
  解码仍可能承载编码带宽只有 8 kHz 的内容。提高设备名义采样率不能补回音源丢失的频率。
- [Signalsmith：Designing a straightforward limiter](https://signalsmith-audio.co.uk/writing/2022/limiter/)：
  瞬时改变增益会造成失真；对受峰值约束的增益做有限长度平均，可配合前瞻延迟平滑攻击并
  维持上限。本轮按这一数学思路独立实现，复用工程原峰值环，没有引入该库或复制其代码。
- [乐鑫 DRC](https://github.com/espressif/esp-adf-libs/blob/master/esp_audio_effects/docs/README_DRC.md)
  与 [Audio Effects](https://docs.espressif.com/projects/esp-adf/en/latest/basic-components/effects/esp-audio-effects.html)：
  提供增益平滑、attack/release/hold 等成熟机制。多段压缩或换一套 EQ 需要额外调参和硬件
  频响依据；已有一条保护链，本轮只补齐其攻击平滑，避免引入一整套未经实测的动态处理。
- 本工程输出重采样已使用当前组件最高 complexity 3，ES8311 按本板配置输出 24 kHz。
  因麦克风、DAC 参考和输出共用双工 I2S，不在缺少对照测量时改成 48 kHz，避免增加采集
  转换和实时负担。数字采样峰值安全也不能证明功放、扬声器或腔体没有失真。

| 方案 | 本轮处理 |
| --- | --- |
| 保持现有服务端 Opus，修订设备输出限幅 | 已实现；可减少峰值调制产生的粗糙感，保留音量与保护 |
| 提高服务端音乐源/转码质量 | 新日志提供依据；目前没有云端配置或原曲样本，未擅自修改服务 |
| 设备直接下载 MP3/AAC | 需新的 URL、安全校验、解码缓冲与对话取消流程；现有服务未下发此契约，未临时拼接第二套播放器 |
| 去保护、加低音或强行推高音量 | 没有硬件测量支持，不作为本轮方案 |

## 实现与上限证明

新增 `AUDIO_SPEAKER_SMOOTH_LIMITER`，默认关闭；小熊猫普通入口和打断入口启用。
保持现有 EQ、0.5 dB 补偿、120 Hz 高通、RMS 保护和 0.84 峰值上限，NVS 音量不变。

旧限幅器在检测到未来峰值时立即改变当前增益，虽有 1 ms PCM 延迟，攻击仍是一步到位。
新实现对峰值/释放约束后的增益做 `L+1` 点平均；`L` 就是原先 1 ms 的样本数。
24 kHz 时仅新增 25 个 Q20 整数增益值（100 字节），每采样常数开销、没有扫描窗口或分配。

设当前时刻为 n，实际输出是 x[n−L]。此前 n−L 到 n 的每个峰值窗口都覆盖 x[n−L]，
因此各自增益均不高于该输出样本允许的上限；其平均也不超过上限。Q20 向下取整，并用
32 位整数维护精确和，避免长时间运行的浮点累积漂移。8～48 kHz 的窗口和最多为
49×2²⁰，低于 uint32_t 上限；不支持的采样率回到原处理。最后只按原峰值门槛兜住浮点舍入。

输出长度、播放速度、1 ms 前瞻和起播淡入时序保留，跨 Opus 包持续处理；原有 writer-owned
reset 清除新增历史。关闭该开关与 803361e 旧实现的输出逐样本一致。处理仍发生在 DAC 前，
ES8311 参考包含实际处理后的信号，没有换成处理前的软件参考。

## 音源统计

同一开关启用 `DecodedAudioStats`：仅在成功解码后、重采样/EQ 前，累计约三秒实际 PCM
时长并打印 `Opus quality:`。包含解码/输出采样率、负载平均 bps、编码带宽范围、编码双声道
包数、SILK/HYBRID/CELT 包数、PCM 峰值、恰落在 int16 边界的样本数和解码失败次数。

- 码率以实际解码样本时长计算，支持 VBR；不包含网络/传输头的开销。
- 编码带宽是 TOC 声明的可用编码频宽，不等于实测原曲频谱或主观保真度。双声道计数描述
  编码包；本板依旧单扬声器单声道播放。
- rail 样本表示数字边界命中，不足以独立断定原始录音已经削顶；也看不到模拟功放失真。
- 同样观察本地 Opus；日志不能自行区分音乐、TTS 或离线声音。换代次或采样率清历史，
  不保存包/PCM、不发送录音、不创建额外音频任务，也不改变队列和协议语义。

后续若原曲播放段持续显示较窄编码带宽或较低码率，必须再检查服务端音源/转码。即使编码
带宽显示 fullband，24 kHz 输出的物理奈奎斯特上限仍是 12 kHz，不能称为 20 kHz 高保真输出。

## 自审、测量与验证

以 `803361e` 的生产头文件为对照，使用相同 24 kHz mono int16 输入，直接编译运行新旧
处理器；对照程序、测量数据和未经额外归一化的 WAV 位于固件目录 review 下。

| 检查 | 结果 |
| --- | --- |
| 鼓点叠加 200 Hz 底音，扣除自然底音变化后的攻击阶跃，24 kHz | 384 → 38 PCM 计数，减少约 90.1% |
| 同一鼓点测试，8/12/16/24/48 kHz | 阶跃减少约 74.4%～94.9% |
| 9 段：自主合成的乐器/打击乐片段、高电平混合音、7 段已有中文提示音 | RMS 变化 0～+0.00362 dB；FFmpeg 响度变化按其输出精度均为 0.00 LU |
| 这 9 段输出的最大采样峰值/满幅样本数 | 最大 27524 / 32767；满幅样本 0 |
| 关闭新开关与原生产实现 | 9 段逐样本一致 |
| 全量主机检查 | 243 项通过，81.216 秒 |
| 扬声器与音源统计 ASan/UBSan | 共 13 项通过；11 项扬声器检查中 10 项执行原生代码，另 1 项为配置检查 |

上述阶跃指标只证明特定测试的增益调制更小，不是“主观音质提高 90%”。样本没有用户所播
原曲，也未覆盖真实扬声器、电池、电源、机身共振或全部音乐。不能以数字测试替代试听。

自审覆盖极值/随机 PCM、峰值边界、任意分块一致、reset 与重配置、起音延迟、静音及旧路径
一致；统计覆盖全部 32 个 TOC 配置和声道位、VBR、失败计数、换会话/换采样率和非法参数。
S3 构建额外校验了主机与 Xtensa 的 uint32_t 类型差异，已统一比较操作的类型。
应用、两种协议、AEC/NSNet2/VAD、打断门控、ES8311 和本板引脚与 803361e 逐文件一致。

普通小熊猫、打断实验入口及 C3/4G 代表配置均构建通过；本机使用 ESP-IDF 6.0.1，优先
版本 6.0.2 尚未安装。兼容性检查后恢复 S3 小熊猫打断入口，不保留 C3 作为当前烧录目标。

## 实机仍需验证

电池状态下对照沙哑/发闷/鼓点破音和响度；保留安静片段、人声、密集乐器与大动态样本。

播放、停止/重启、静音、双击退出及原人声打断。人声打断仍须独立实机验收，本轮没有称它
