# 小熊猫播报音质与响度（2026-11-04）

用户明确希望改善播报含糊、发闷或破音，同时音量不能太小。本轮只调整扬声器 PCM 处理。
普通人声误打断仍未通过验收，不把本次音质改动当作它的修复。

## 调研与取舍

- 现有播放已经使用 24 kHz ES8311 输出；需要重采样时，输出转换器已经是该版本最高的
  complexity 3。提高名义采样率不能补回云端/原始录音没有的内容，当前没有理由改时钟。
  [乐鑫 rate conversion 接口](https://github.com/espressif/esp-adf-libs/blob/master/esp_audio_effects/include/esp_ae_rate_cvt.h)
- 乐鑫提供 EQ、Fade 和 DRC 等输出处理。当前工程已有一条带高通、响度保护和前瞻限幅的
  统一播放路径，适合在该路径内做小改动，保持在线 TTS、本地声音和参考一致。
  [乐鑫 Audio Effects](https://github.com/espressif/esp-adf-libs/blob/master/esp_audio_effects/README.md)
- 均衡器使用 W3C 收录的 RBJ peaking EQ 公式。300 Hz 小幅削减、2.5 kHz 小幅提升是针对
  用户“发闷/含糊”的保守候选，不是根据本机扬声器频响测得的补偿曲线，仍需试听。
  [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)
- 乐鑫要求检查播放失真、腔体/隔振和电源。软件数字峰值安全不代表功放/喇叭在同一音量下
  没有失真；若破音来自硬件，必须在实机上测量定位。
  [乐鑫声学设计指南](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/Espressif_Microphone_Design_Guidelines.html)

## 实施

新增 `AUDIO_SPEAKER_VOICE_CLARITY`，默认关闭，仅小熊猫普通版和打断测试版在 config.json
启用；板型、引脚、分区与声音资源格式保留。

新路径为：120 Hz 高通 → 温和 EQ / 0.5 dB 补偿 → 原响度保护 → 原 1 ms 前瞻峰值限幅 →
起播平滑 → ES8311。保护参数保留为原来的 0.84 采样峰值上限、0.25 RMS 门槛、0.63 最低
响度增益，以及既有时间常数。没有把音量设置强制调低或改成某个固定值。

具体调整：

- 300 Hz、Q 0.8、-1 dB；2.5 kHz、Q 0.8、+2 dB。两级后加 0.5 dB 补偿，均在保护之前。
- 原路径用未衰减信号独立计算峰值增益，再乘响度增益，在某些响亮素材上会重复降低响度。
  新路径先应用平滑后的响度增益，再测真实待输出峰值，使用余下的数字余量。
- 每次已有 DSP reset 后，在 1 ms 延迟线开始输出真实样本时做 5 ms smoothstep 起播。
  不按 Opus 包重新启动淡入；不添加等待或改变 PCM 长度、播放速度。
- EQ 系数只在初始化计算。逐样本没有新建容器、动态分配、I2C 操作或阻塞等待。
- 关闭新开关时维持原 DSP 行为。麦克风增益、VAD/AEC、Opus 网络参数和 NVS 音量均保留。
- ES8311 数字参考来自实际 DAC 路径，输出处理仍发生在 `Write()` 前；没有另外拼接一个
  未经 EQ 的软件参考。音质变化后打断仍需重新做物理验收。

## 自审与离线数据

使用修改前的实际 `SpeakerProtection` 作为基线，与新生产头文件编译为同一主机比较程序。
输入为工程中七段已有中文提示音，FFmpeg 转为一致的 24 kHz / mono / int16 PCM；比较的是
处理后 PCM，未对试听文件额外归一化音量。

| 指标 | 结果 |
| --- | --- |
| 七段输入 | welcome / wificonfig / upgrade / err_reg / err_pin / 0 / 5 |
| RMS 相对变化 | -0.136～+0.344 dB |
| FFmpeg 测得响度相对变化 | -0.16～+0.43 LU |
| 新输出 int16 削顶样本 | 0 |
| 所测采样峰值最大值 | 27524 / 32767 |

这些短提示音数据只能证明该小样本没有被大幅压小，不能代替故事 TTS、全部声音素材或真实
扬声器的响度/音色验证。PCM 采样峰值限幅不等于经过过采样验证的 true-peak limiter；
本轮也记录了 FFmpeg 估算的 true peak，未将约 -1.5 dBFS 的采样门槛误称为绝对模拟保证。

主机检查覆盖 8/16/24/48 kHz：温和频响、正常语音混合信号的电平保留、响亮信号的余量、
极值/随机 PCM 峰值、分包一致、起播平滑一次性、重置清状态、关闭增强恢复原路径。
另对关闭增强的生产实现与原实现做随机分块逐样本比较，四个采样率均一致。

验证状态：全量 230 项主机测试通过（95.635 秒）；9 项扬声器针对性测试在 ASan/UBSan
编译环境下通过，其中 8 项原生 C++ 用例启用检测。普通小熊猫、打断测试入口和 C3/4G
均构建通过，使用本机 ESP-IDF 6.0.1；
本机未安装项目优先使用的 6.0.2。C/C++ 格式与差异空白检查通过。

## 固件与实机验收

本地候选和复核材料放在 `dist/wzh-tailredpanda-audio-quality-20261104/`。普通入口与打断
测试入口分开保存，清单记录镜像哈希和尺寸。打断入口是未验收实验，不能描述为稳定人声打断。

实机验证尚未完成；目前电脑未识别到 USB 串口。本轮不能据编译或离线数字波形宣称真实听感
已改善。后续在相同音量、相同摆放和近似电池状态下对比：

1. 正常音量播报相同故事，检查清晰度、齿音、薄声、底噪与句间衔接。
2. 常用较大音量播放高峰值句子和本地音效，检查破音、供电和机身共振；保留用户可接受的响度。
3. 检查起播首字、连续播报、停止/重新开始、静音、双击退出和重连。
4. 打断测试入口额外检查纯播报误触发和普通人声打断，单独记录验收结果。

回退音质处理时，在板级构建配置将 `CONFIG_AUDIO_SPEAKER_VOICE_CLARITY` 设为 n，使用
`scripts/build.py` 重新生成构建；不要手工编辑 sdkconfig 或移除已有扬声器保护。
