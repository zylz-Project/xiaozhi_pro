# 小熊猫普通人声打断：实时性修订与自审（2026-11-04）

本轮代码修正针对用户最新日志证明的实时过载。上一版 NSNet2/VADNet 候选未通过实机，
本轮也不能以软件构建代替“安静不自断、正常说话能打断”的实机验收。

## 已确认的故障

- 75.671 s：神经后处理单批耗时 `45145/32000 us`，超过该批音频的实时预算。
- 79.181 s：CPU1 的 `IDLE1` 看门狗告警；当时 `audio_afe` 调用栈仍在跑额外的
  MultiNet7 本地命令识别。89.181 s 又出现告警，当时在神经卷积代码中。
- 79.581 s 起反复出现 `AFE(FEED) is full`，同时有编码队列丢帧。
- 监测已开启、播放参考曾有效、没有记录输入削顶；现有数据不能将漏检简单归为“阈值太高”。
  超时和持续丢帧使音频链不能可靠实时处理，须先解决这一条件。

[ESP-IDF 看门狗说明](https://docs.espressif.com/projects/esp-idf/en/v6.0.1/esp32s3/api-reference/system/wdts.html)
说明 IDLE 任务长期得不到运行会触发 TWDT；
[ESP-SR 官方基准](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/benchmark/README.html)
中的组件性能不能替代本板完整链路的实测预算。此次没有关闭看门狗或扩大队列掩盖过载。
成熟路线对照及第三方库许可结论沿用[上一轮调研](wzh_tailredpanda_neural_barge_in_2026-11-04.md)。

## 本轮实现

```mermaid
flowchart LR
    MR[麦克风与 DAC 参考] --> AEC[FD AEC]
    AEC --> NS[NSNet2：512 样本]
    NS --> VAD[WebRTC VAD：160 样本]
    VAD --> PACK[对齐为 960 样本编码包]
    PACK --> GATE[参考／能量／回声否决／持续时间]
    GATE --> APP[主任务复核并取消回复]
```

1. 保留 AEC 后 NSNet2，移除每帧额外的独立 VADNet 推理。采用 ESP-SR 已提供的 WebRTC
   VAD API：16 kHz、10 ms、mode 2、60 ms 起音、100 ms 静音确认。选择依据是本板已出现
   的计算超预算；换轻量 VAD 的分类准确率须重新测试，不宣称准确率等同 VADNet。
2. NSNet2 的 512 样本与 VAD 的 160 样本不能整除。新增固定的 160 样本缓冲，跨帧保留余数，
   再按现有 960 样本编码。只在完整 VAD 块上调用 API，不补零、不丢余数，不给整包套用
   最新一块的状态。会话结束丢弃尚不足一块的尾部，切换时清除所有半帧。
3. 仅神经打断候选在在线语音处理期间暂停“附加本地 MultiNet 命令”路径。保留主唤醒 WakeNet；
   将 MultiNet 作为主唤醒的其他配置不受影响。恢复待命时重新启动本地命令识别并清掉旧半句。
   在线身体命令仍走原云端 MCP。此取舍意味着在线不再额外跑同一套离线动作口令识别。
4. 每 64 批输入记录神经后处理平均/最大耗时与附加 MultiNet 暂停状态，超实时预算仍告警。
   该耗时包含后处理及其输出回调，不包含 AFE 内部全部计算和完整系统负载，不能据此单独
   宣称 CPU 总占用达标。
5. 测试入口选择 WebRTC VAD，资源只要求 NSNet2；通用资源生成器仍能为其他配置打包 VADNet。
   保留缺模型时不进入自动打断、generation 过期结果丢弃、参考失效撤销候选和主任务复核。
6. 扬声器 EQ、峰值/RMS 保护、音量及 ADC 6 dB 配置均保留；没有改 I2S 时钟、硬件引脚、
   电源/舵机保护和原有两种网络协议。

## 自审范围

- 逐采样验证 512→160 重分帧，包括 511/5 等不整齐输入和多个周期；检查输出次序、采样内容
  与语音状态。生产适配层编译运行于 SDK 替身，不以替身测试声学效果。
- 会话 reset 清除旧波形和两种半帧；NSNet2 无重置 API，仍用两个静音 hop 推进其分析窗口，
  WebRTC 重置触发状态，不宣称清除了其全部内部噪声估计历史。
- 推理中退出会话不交付旧 PCM；检查缺模型、错误格式、分配失败及重复关闭。
- 主唤醒/附加命令 × 特性开关共十组配置验证：在线只暂停附加 MultiNet，不重复 Stop，待命
  恢复，主 MultiNet 唤醒路径保留。
- 实际构建资源解包，校验长度、校验和、模型表与边界；NSNet2 的模型文件逐项与源文件比较，
  确认新实验入口没有打包未选择的 VADNet。

- 全量 239 项主机检查通过（92.750 秒）。核心前端/唤醒路由 7 项与既有打断链路 18 项，
  共 25 项在 ASan/UBSan 下通过（分别 3.186、5.315、8.949 秒）；C/C++ 格式与差异空白检查通过。
- 使用本机已安装的 ESP-IDF 6.0.1；6.0.2 尚未安装。S3 实验入口、S3 普通入口和 C3/4G
  代表路径均构建通过。普通入口与 C3 关闭神经前端；普通入口资源 SHA-256 与上一版对照一致。
- 本轮只修改前端、实验入口配置及对应打包/测试/文档；扬声器 DSP/codec、打断门控、应用及
  WebSocket/MQTT 协议实现逐文件与原 HEAD 核对一致。

不收入公开 ZIP。

## 实机验收仍待完成

电脑当前未枚举到样机串口，本轮没有烧录或录得新候选的运行日志。下一轮先核对启动标识
`FD AEC -> NSNet2 -> WebRTC VAD; NS=512, VAD=160 samples`，再检查连续长播报期间没有
TWDT、AFE 缓冲溢出和持续编码丢帧，平均耗时低于音频预算且有供 AFE/编码/系统使用的余量。
正常间歇调度的单次最大值不应孤立用作整链路通过标准，须看累计超时与队列是否持续积压。

随后在用户实际音量下分别验证纯播报、正常近距离双讲、句间起音、短命令、连续对话、
唤醒、双击进出和重连，记录误取消、漏检、延迟及首字。能量/相关性门控仍是启发式，保留
180 ms 确认和 300 ms 起播稳定条件；本轮没有证据支持盲目放低门限。若仍不能可靠区分
残余 TTS 与人声，应使用同一批原始 MR 对照完整双讲前端，而非把 VAD 阳性当作用户真值。
